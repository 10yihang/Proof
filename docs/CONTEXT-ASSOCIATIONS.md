# 文件与会话关联

此实现对应 PRD 的 CTX-04，并补充 CTX-01/03、EVD-01 的文件级阅读入口。History 仍选择比较对象并打开独立 Diff tab；这里的操作位于 Changes 当前文件的 Context 面板。

## 交互

- 默认显示相关会话摘要、任务摘录及关联理由。原始事件按会话展开，每次读取 20 条；任务、命令、输出和最终回复保留原文。未授权字段显示“未开启记录”，命令退出状态与结构化测试、当前 Diff 的验证状态不混用。
- “关联会话”只搜索当前 Worktree 的已捕获会话，可按 Agent、原生/本地 Session ID、Subagent ID 或任务搜索，每页 30 条。按会话首次登记时间和 ID 使用游标翻页，新活动不会把未读会话移出分页范围。来源会话清理后仍可找到保留期内的本地备注；不会跨 clone/Worktree 合并原生 ID。
- 用户可关联、解除、填写最多 2000 字备注，或恢复按原始记录关联。手动修正标注“用户指定”。修改记录包含前后备注、当时的原始线索、用户来源和撤销链。
- 每个文件/会话的最新修改可撤销；撤销追加一条历史，不删除原记录。关联和修正历史分别按最近更新时间、创建时间保留 30 天。原始事件清理后，保留期内的本地备注可显示，但不会重建原始事件。
- 编辑时保留预期版本和草稿。另一窗口更新后，旧保存会被拒绝；用户可读取最新关联，核对保留的输入后再次保存。切换候选会话保留本次弹窗内的各个草稿，关闭弹窗放弃未保存输入。保存已经发出时可以关闭，失败会显示在主界面。

## 数据与性能

修正写入 `observer_associations` 和 `observer_association_history`，在同一个 SQLite Immediate 事务内更新。历史写入失败时，关联同步回滚。版本包含本地数据代次、观察策略代次、会话登记时间、同一文件/会话最新历史 ID、当前覆盖值以及历史删除代次。尚未清理的到期历史仍参与版本检查；数据库删除触发器更新无内容的 `context_history_epoch`，防止历史清理后旧版本再次有效。全局删除保留该计数器，不需要重启才能继续使用 Context。其他会话的普通修正不使当前编辑失效；历史清理会要求重新读取。

普通 Context 读取只查询本地记录并检查路径边界，不启动 Git；不要求维护写入才能遮蔽已到期输出。显式修正前验证实际 Worktree 身份，路径不能跨 Git 内部目录或嵌套仓库。保存结果在事务内生成；不会把成功提交后的刷新错误误报成保存失败。清理观察记录/删除本地数据沿用既有代次失效和内容清理流程。

事件数量增加时，已展开的页保持不变，提供“读取最新记录”入口。每页返回记录和输出的实际保留期限；界面按秒检查，并在窗口恢复焦点/可见时重新检查，只移除已到期的内容，其他记录及其展开状态保留。清理不依赖事件数量变化。

文件级线索不构成当前 Diff 的独占作者结论。有写入负载与捕获文件一致时，在“关联依据”中说明其时间范围，不将之后的整个 Diff 自动归给此事件。逐 Hunk 归属及完整的验证时效推导仍属于后续工作。

## 设计参考

参考 [GitKraken 的 Agent 会话与 Worktree 导航](https://support.gitkraken.com/gitkraken-desktop/agents/)和 [GitHub 在对象侧栏管理关联的选择器](https://docs.github.com/en/enterprise-server%403.21/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)，采用当前文件内的摘要与按需管理入口。这里只借鉴导航和关联选择模式，不声称这些产品提供相同的人工证据修正功能；Proof 继续观察外部 Agent，不启动新的 Agent 会话。

## 验证范围

核心定向测试覆盖关联/解除/备注/恢复/撤销、原始事件与 Git 字节不变、跨 clone/Worktree/原生子 Agent 的隔离、无原生 ID 的本地会话、版本冲突、事务回滚、到期/清理、分页、越界路径和仓库替换。页面测试覆盖草稿冲突、延迟失败、窄窗及延迟读取事件；实际 Git/SQLite 的 UI 流程也加入关联和撤销检查。最终结果以本轮 ACCEPTANCE 和评审记录为准，尚不能据此宣称完整 PRD 已验收。
