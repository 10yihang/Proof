## Standards

1. **明确违规：过期工作区请求能覆盖当前界面。** 对应 PRD 17.2。`App.openWorkspace` 缺少请求代次，`loadFile` 和信任回调也存在跨工作区返回窗口。已增加 workspaceEpoch、接纳工作区时使旧读取失效、核对返回 worktree ID，并隔离旧错误/审查/写操作回调。最终源码复核通过；并发 UI 的专项自动化仍需补齐。
2. **判断项：用正文字符串猜文件类型。** `service.file_diff` 原先扫描整个 patch 的数字与文本，普通源码可能被识别为子模块。已用 `FileKind` 与结构化文件头替换，新增正文伪装元数据、普通文件转符号链接的真实 Git 回归；多段 patch 统一按文件处理。
3. **明确违规：提交失败原因在模态框背后。** 对应 DESIGN 的错误可见规则。Modal 现在显示可访问错误，提交、打开/信任仓库、设置和创建分支均接入并保留输入。源码与类型检查通过，更新版原生错误弹层复验待 Mac 解锁。

Standards：2 项明确违规、1 项判断；最严重的是工作区请求串入，已修复。最终限定范围内未发现新问题。

## Spec

1. **P1：并发 index 更新使所选 Hunk 错位应用到重复上下文。** 对应 GIT-01/04。改为持有真实 index.lock 的私有索引事务，锁后和发布前重校验，原子发布并核对完整 index 字节。外部 update-index 故障注入回归由红转绿。
2. **P1：Hook 切换到同父提交的另一分支，提交仍显示成功。** 对应 GIT-03/04。现在核对实际分支和预览目标引用，返回实际提交并突出不匹配。
3. **P1：局部文本暂存夹带文件执行权限。** 对应 DIFF-04、GIT-01。局部 patch 去掉 mode 变更；模式改变成为独立审查项，文件级动作包含完整变化。
4. **P1：类型变更的第二个文件头遗漏，可能生成空目标符号链接。** 元数据解析覆盖每个 `diff --git` 段，跳过正文；多段或 `T` 状态不提供局部文本暂存。真实测试验证文件级操作保留 120000 模式与正确链接目标。
5. **P2：Hook 重命名预览分支后，成功产生的提交被报为普通 Git 失败。** 原引用不存在现在视为核对不匹配，保留实际提交、实际分支和警告。

Spec：5 项已证实问题均修复，最严重的是暂存选择范围错误。独立副本最终验证原有 5 个 spec 回归和 2 个后续回归全部通过；split-index、linked worktree 和 unborn 路径也有实际验证。最终限定范围内未发现新的阻断项。
