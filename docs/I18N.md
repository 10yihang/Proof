# Interface languages

Proof supports 简体中文 (`zh-CN`, the existing default) and English (`en`). Change the language in Settings → Appearance and reading → Language. The choice takes effect immediately without remounting the workspace or clearing the Commit draft, selected files, open Diff tabs or reading state.

## Copy and terminology

The Chinese interface uses Chinese for ordinary actions, explanations and statuses. Git terms remain in English where they name concepts or operations: Git, History, Commit, Review, Diff, Branch, Worktree, HEAD, Index, Stage, Unstage, Amend, Merge, Stash and Blame. Product and executable names such as Proof, Codex and Claude Code retain their names. Examples: `Review 当前变更`, `AI 分组`, `Stage 全部`, `在独立窗口打开`.

Catalogs are `src/i18n/zh-CN.json` and `src/i18n/en.json`. Keys retain the original source messages to make the extraction auditable; change the displayed copy in both catalogs rather than renaming keys casually. `t()` accepts a typed catalog key and named interpolation values. Numeric placeholders in English templates handle the supported singular count forms. Dates and number formatting use the chosen locale; the system timezone remains unchanged. The document language and accessible labels update along with visible copy.

Only authored UI copy is translated. File and Branch names, source code, raw Patch, Commit messages, author names, Hook configurations, command output, notes and existing AI report content remain literal data. The app does not walk or rewrite the rendered DOM. `uiMessage()` is restricted to Proof-owned feedback fields; it matches catalog entries and captured interpolation values, retaining unknown messages and raw diagnostic details. It must never be used as a generic wrapper around repository or Agent content.

## Storage and lifecycle

`ui_language` / `set_ui_language` read and write a validated `UiLanguage` in Proof's existing SQLite settings table. The language is separate from reading preferences, so saving another window's font or Diff settings cannot overwrite it. Existing databases default to Chinese. Repository record deletion retains the global preference; deleting all Proof records resets it with other application settings. Browser demo mode stores only the language preference in browser storage.

Cross-window notifications invalidate the preference and read SQLite again. Reads and saves are guarded against obsolete renderer/data generations; a notification arriving during a save is reconciled afterward. A failed save retains the previous language and displays an error. macOS menus read the same committed preference. No operating-system language setting or Coding Agent configuration is modified.

An active AI task captures the language when prepared. Its new Grouping/Review output is requested in that language, while Git terminology stays in English. Changing the language cannot rerun AI, affect an in-progress task or translate an existing report.

## Validation

Catalog checks enforce identical keys, non-empty English values and matching interpolation parameters. Unit tests cover technical terms, singular/plural numeric placeholders, literal user values and localized backend feedback. Core tests cover persistence, independent reading settings, unsupported locale rejection, data cleanup and the captured AI output language. UI tests cover switching, reopening, backend errors, failed saves, draft/source preservation and the existing Git workflows. Packaged macOS menu code is compiled; native GUI execution requires separate host authorization.
