# Proof UI 与性能改进 · 2026-10-04

本轮已分阶段完成前次审查提出的 UI、动画和性能改进，保留现有 macOS 工作台、Commit/History/Files 布局与不透明代码表面。改动在隔离工作树完成，整合时逐文件比对原工作区指纹，保留此前未提交的内容。

## 已完成的阶段

| 阶段             | 结果                                                                                                                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 审查到提交       | 全局审查摘要分别显示已加载文件版本、已加载 Hunk 的审查数和未加载范围；“下一未审查文件”只导航，不自动标记或暂存。Commit 默认读取 Staged 版本，常驻本次暂存范围；读取 Unstaged 候选时明确该版本不在提交范围内，并提供返回 Staged 的入口。                        |
| 阅读、证据和动画 | 低频上下文、全文、历史、外部编辑器等选项归入“阅读工具”；Hunk 审查按钮有可见文字。证据先展示当前快照与验证边界，活动按需展开；空态支持关联已有会话。代码字号滑块有正确的可访问名称，减少动态效果统一为轻量反馈，键盘操作仍立即响应。                            |
| 前端与刷新       | Settings、History、Files 相关页面延后加载，并提供等待/取消反馈。Changes 与 Commit 保存各自的阅读位置，返回 Changes 恢复原文件。Context 在隐藏或非活动状态停止轮询，回到前台立即刷新，丢弃过期结果；前台仍保留 2.5 秒兜底，因为 Observer 没有完整的推送生产链。 |
| Core 与原生后台  | Context 批量聚合并建立派生路径索引；比较准备复用固定快照中的文件清单；History 复用有界顺序块。Observer 的进程启动与 heartbeat 等待移到 Core 锁外。文件监听合并路径并批量核对 Git ignore，已跟踪文件、Git 元数据、溢出及失败仍触发保守刷新。                    |

提交、丢弃、审查标记的既有确认和版本保护保留。审查统计不会为了填满分母预加载全部大文件；Comparison 的内存预算计入保留的 Diff 结构和元数据，而非仅计 Patch 字符数。

刷新事件包含 workspace、generation 与路径信息；前端同时兼容旧字符串事件，但对象事件必须匹配当前 workspace/generation。Files 编辑器复用这条经过校验的刷新链，避免旧监听结果影响当前工作区。监听所用 Git 来自 Core 已验证的配置，清理继承的 Git 路由和 pathspec 环境变量；独立 Git 目录仍按元数据处理。

## 测量结果

Core 数字来自相同 Debug 夹具与测量方式的中位数，Context 各 5 个样本，其余各 3 个。它们说明这些代码路径减少了重复工作，不能代表发布包的端到端点击延迟或 p95。

| 场景                       |      改动前 |     改动后 | 工作量变化                           |
| -------------------------- | ----------: | ---------: | ------------------------------------ |
| Context：1 万事件、1 会话  |    92.54 ms |   69.95 ms | SQL 18 → 9                           |
| Context：1 万事件、30 会话 |   157.79 ms |  106.22 ms | SQL 366 → 9                          |
| Comparison：100 文件准备   |  3719.75 ms | 1292.44 ms | Git 进程 306 → 106，清单查询 101 → 1 |
| History：1 万提交、100 页  | 10483.24 ms | 6528.90 ms | 祖先遍历 100 → 10                    |

生产构建主 JS 从 1837.29 kB（gzip 558.54 kB）下降到 1613.97 kB（gzip 502.31 kB），约减少 12% / 10%。Settings、RepositoryView、EditorView、HistoryDiff 形成独立延迟加载块；Monaco 和 xterm 继续按需加载。体积变化不是启动耗时测量。

延迟 heartbeat 夹具中，锁拆分后普通 Core 偏好读取可以在约 72 µs 内获得锁。200 个被 Git ignore 的输出路径夹具从一次 invalidation 降为零；这两项是针对边界的合成验证，不是实机平均响应时间或 CPU/RSS 数据。

## 验证与证据

- 前端单元测试：28 个文件、118 项通过；类型检查和生产构建通过。
- Rust 串行回归：25 个测试套件、354 项通过、0 项失败、17 项忽略。忽略项包括需要真实 Agent 的场景和单独执行的合成基准；本轮没有调用模型或修改真实用户数据库。
- Core、Observer、Desktop 的相应 Clippy 检查通过。真实 macOS 文件通知测试在可接收文件系统通知的环境执行，覆盖重命名、Git 元数据、特殊目录、污染环境变量和 ignored 输出。
- 系统 Edge 分批通过 147 个不同 UI 场景，覆盖 Changes/Commit/History/Files、全文读取/取消/恢复、真实 Git 夹具、快捷键与减少动态效果；保留原始源行和提交保护断言。最后的 Changes → Commit → History → Changes 回归还核对原文件、源行、行内偏移、内容与提交草稿。1440 桌面与 1024×720 最小窗口、中英文均保存截图。
- 全量浏览器选集与定向复测是分批结果，不能写成同一次运行、同一源码快照的全量通过。早期旧模块/菜单定位失败和最终定向通过日志一并保留。

证据位于 `.artifacts/ui-performance-2026-10-04-implementation/`：`core/` 保留原始样本、测量命令和代码来源；`ui/` 保留浏览器、构建、Rust 日志与六张截图；`integration.json` 记录整合文件指纹。

## 发布边界

派生路径索引将数据 schema 从 7 升到 8，事务回填及失败回滚已用测试数据库验证。旧 schema-7 二进制不能打开已经升级的 schema-8 数据库；后续打包必须同时构建匹配的 Core 与 Observer。验证用 Debug sidecar 不作为发布产物整合。

本轮完成的是本地源码实现、构建、夹具和浏览器验收，没有发布安装包，也没有测量原生 WebView 的冷启动、完整点击链路 p95 或 CPU/RSS。原生共享锁和文件监听的修正有针对性运行证据；Edge 演示与真实 Git 测试传输不能代替打包后的 Tauri IPC 验收。
