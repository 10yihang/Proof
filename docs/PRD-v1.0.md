# Proof｜AI 编码审查 Git 客户端产品需求文档

**文档版本：** v1.0（待评审草案）  
**交付基线：** 产品 v0.1 MVP  
**日期：** 2026-09-12  
**品牌名：** Proof（用户已确认）

> 让用户继续用喜欢的 Agent 写代码，用真实 Diff、可核对证据与人工审查，看清每一次修改。

性能和准确性指标为拟定验收目标，并非已完成的实测结果。

# 01｜产品概要与文档约定

## 1.1 产品定位
**一个面向 AI 编码时代、以人工 Diff / Code Review 为核心的本地 Git 客户端。** 用户继续在外部终端或 IDE 使用 Coding Agent，本产品把真实代码变化、相关任务和可观察执行记录放到同一个审查工作台中。Agent 不必由本产品启动，也不需要迁移到本产品内部。

产品首先是可独立使用的 Git GUI，其次才是具有 Agent 上下文的审查工具。核心承诺是：让人看清修改、保留判断权，而不是由另一个 AI 自动批准代码。

## 1.2 文档元信息
| 项目 | 定义 |
| --- | --- |
| 产品名称 | Proof；面向 AI 编码的本地 Git / 人工审查客户端 |
| 文档版本 / 状态 | PRD v1.0 / 待评审草案；不是已发布产品说明 |
| 编制日期 | 2026-09-12 |
| 本次交付基线 | 产品 v0.1 MVP；同时描述后续能力边界 |

| 事实与提案 | 上游能力注明资料编号；产品规则、指标、默认值均是本 PRD 的设计提案 |

## 1.3 不可妥协的原则
**代码优先。** 真实 Git 状态与代码内容是核对依据，AI 分析不覆盖原始 Diff。**人工决定。** 已查看、已暂存、已提交和验证通过是不同状态。**旁路接入。** 观察模块不主动改变 Agent 的上下文、工具、权限或决策。**诚实降级。** 证据缺失显示未知，不用时间相关性伪装因果关系。**本地优先。** Git 与人工 Review 无账号、无模型服务也可使用；核心 AI 功能仅在点击后使用本机 Coding Agent 的现有登录。

## 1.4 需求与优先级约定
需求编号采用 REPO、DIFF、GIT、REV、OBS、CTX、EVD、AI、SET、NFR 等前缀。P0 是 v0.1 上线条件；P1 是后续增强，不阻塞 MVP；P2 是远期方向。文档版本号不等于产品版本号。

“必须”是验收条件；“建议”允许在技术评审中调整并留痕；“待验证”必须由原型或测试关闭，不可直接对外宣传。本文所有性能数值均为**拟定目标，尚未实测**。

# 02｜问题、用户与目标

## 2.1 问题定义
当前讨论暴露出三个需要验证的用户问题：外部 Agent 的任务背景与 Git Diff 分离；大量或持续变化的代码难以记录审查进度；历史测试、修改来源和最终代码之间的关系容易被误解。这些是产品假设，不代表已经完成市场调研或证明所有 Git GUI 都缺少相关能力。

## 2.2 目标用户
| 用户 | 典型场景 | 优先需求 |
| --- | --- | --- |
| U1：外部 Agent 使用者 | 在终端使用 Codex / Claude Code，再回 GUI 看代码 | 不换工作环境；任务与 Diff 关联；提交前逐段核对 |
| U2：人机混合开发者 | 自己编辑代码，同时让 Agent 处理局部任务 | 识别混合修改；不把人工改动错误归给 Agent |
| U3：纯 Git GUI 用户 | 不接入 Agent，日常看 Diff、暂存、提交 | 基础操作完整、快速；不被 AI 界面打扰 |
| U4：多会话使用者 | 多个 worktree 或同一工作区并发修改 | 不串工作区；并发时明确归属不确定性 |

首版以 U1、U2、U3 为主。U4 必须安全处理，但不承诺任意并发下的精确逐行归属。跨设备协作、团队审批和远程 Agent 不属于首版主要场景。

## 2.3 用户任务与成功表现
| 用户任务 | 成功表现 |
| --- | --- |
| 看清真实变化 | 无需 AI 即可看到未暂存、已暂存及新增文件内容，知道当前比较基准 |
| 理解修改背景 | 从当前文件或 Hunk 进入相关任务和事件；无法关联时明确说明原因 |
| 连续完成人工审查 | 记住已审查内容；代码再变时旧标记不能替新内容背书 |
| 安全形成提交 | 只暂存、提交用户选择的内容；冲突和并发不被静默覆盖 |

## 2.4 非目标
不做 Coding Agent Runtime、聊天客户端、自动修复代理或企业 Agent 管理平台；不承诺完整模型上下文、隐藏思考过程、代码绝对正确或合规审计证明；不以首版全面替代成熟 Git 客户端为验收标准。

# 03｜版本范围与能力边界

## 3.1 范围矩阵
| 能力 | P0：v0.1 | P1：后续增强 |
| --- | --- | --- |
| 仓库与工作区 | 打开本地仓库、最近项目、已有 worktree 识别与切换 | Clone、创建 / 删除 worktree |
| Changes / Diff | 文件树、状态过滤、统一 / 并排、Hunk 导航、原始 patch | 更丰富的移动代码展示、跨文件阅读路线 |
| Git 写操作 | 文件 / Hunk Stage 与 Unstage、受保护的单文件 / 多文件 Discard、Commit / Amend、Branch 操作、Fetch / Push / Pull、Stash | 行级 Stage、交互式 Rebase |
| Repository | 提交列表、单提交 Diff、基础文件历史与 Blame | 完整图谱、复杂比较、交互式 Rebase / Cherry-pick |
| 人工 Review | 内容版本绑定、Hunk 标记、审查后变化提醒、专注模式 | 本地评论、导出完整审查报告 |
| Agent 观察 | Claude Code / Codex 的经验证本地版本；显式授权与能力检测 | 更多 Agent、经授权的历史会话导入 |
| 上下文 | 任务、会话、工具与命令证据；可靠的会话—文件关联 | 有条件的 Hunk 精细归属、语义分组与解释 |
| AI 辅助 | 核心功能；显式点击本机 Coding Agent 执行 Grouping / Review，普通 Git 可完全离线使用 | Hunk 级跨组与更丰富分析范围另行设计 |
| 平台 | 暂定 macOS Apple Silicon 首发；Windows 从原型期参与验证 | Windows 正式支持；Linux 另设验收门槛 |

## 3.2 明确不在 v0.1 内
内置终端、内置 Agent / Chat、PR / MR 平台操作、Issue 管理、自动执行测试、自动解决冲突、自动提交或推送、云同步、多人审批、仓库内写入观察说明文件、自动创建 Git Notes 或修改提交作者信息。

## 3.3 降级原则
Agent 未接入、版本不兼容、权限不足或采集服务故障时，Git 与 Review 仍可用；显示“上下文不可用”，而不是锁住 Changes。无法准确处理的特殊 diff 可退化为原始 patch 或只读提示，但不能给出错误的暂存动作。

## 3.4 发布口径
v0.1 可以叫“本地审查 MVP”，不能宣传完整 Fork 替代品。首版适配两类 Agent 的目标不等于支持其所有版本、IDE、云端及远程运行形态；正式支持矩阵以实测为准。

# 04｜核心用户旅程

## 4.1 首次使用：无需 Agent 即可完成一次提交
打开应用 → 选择已有本地仓库 → 检查 Git 与仓库信任状态 → 展示 Changes → 选择文件 / Hunk → 标记已审查 → 暂存 → 查看提交预览 → 输入说明并提交。

Agent 接入不在这条路径中设置强制步骤。无账号、无联网、无模型配置时，此路径仍应成立。

## 4.2 外部 Agent 工作后的审查
在设置中授权指定仓库的观察 → 用户照常在外部终端运行 Agent → 事件进入本地采集服务 → GUI 刷新真实变化 → 用户选择 Hunk → 右侧显示可关联任务和证据 → 人工审查与暂存 → 检查已暂存内容 → 提交。

原型示例统一使用虚构仓库 demo-service；示例任务、日志和测试结果均为演示数据，不表示已读取真实项目。

## 4.3 审查期间 Agent 继续修改
用户正在阅读快照 A → 外部产生快照 B → 当前阅读位置保持稳定，出现“存在新变化” → 已变化的审查单元标记待复核 → 用户切换到最新快照后继续。

禁止在阅读中强制跳转文件、移动光标或把旧 Hunk 的已审查状态复制给新 Hunk。用户从旧视图执行写操作时，必须重新验证内容。

## 4.4 Agent 未接入或中途才接入
没有证据的改动显示“来源未知”。中途安装观察不能自动补齐之前的任务和命令；历史导入须另行授权，且即使导入也不承诺复原每次文件修改的前后快照。

## 4.5 观察失败或退出应用
采集服务失联时，桥接快速结束，不要求 Agent 等待 GUI。若用户已授权后台观察，关闭窗口后本地采集继续；选择“退出并停止观察”后不再采集。恢复后展示空档，不把未收到事件解释为 Agent 没有动作。

# 05｜信息架构与主界面

## 5.1 页面结构
一级工作区为 **Changes** 与 **Repository**。Changes 承担当前代码与审查；Repository 下包含 History、Branches、Worktrees 及只读仓库信息。设置从全局菜单进入，Agent 状态是状态入口，不占据独立主导航。

## 5.2 主界面区域契约
| 区域 | 内容与交互 |
| --- | --- |
| 顶栏 | 仓库、明确的 worktree 路径、分支 / Detached HEAD、最后刷新时间、观察状态、命令面板 |
| 左栏 | 文件树与未暂存 / 已暂存过滤、搜索、审查计数；默认按目录，不强制 AI 分组 |
| 中栏 | Diff 与比较基准、文件 / Hunk 导航、暂存和审查动作；空间占比优先 |
| 右栏 | Context Inspector：任务、来源标签、事件、命令与验证记录；可关闭 |
| 底栏 | 当前筛选范围的审查进度、全局剩余项、选中动作与提交入口 |

## 5.3 布局与视觉要求
设计基准为 1440×900，最小可用窗口暂定 1024×720。宽屏默认左栏约 240px、右栏约 300px，其余留给 Diff；可拖拽调整并按仓库记忆。窄屏先收起右栏，不把代码压成不可阅读的三栏。并排 Diff 太窄时提示切换统一模式，尊重用户选择。

使用紧凑开发者工具风格：层级清楚、状态克制、代码对比度充分。深浅主题同等支持；风险、来源和审查状态不能只靠颜色。字体缩放、键盘焦点、读屏标签和减少动态效果设置是 P0。

## 5.4 关键交互规则
命令面板统一提供可执行动作与禁用原因。快捷键在输入框、编辑器输入、中文输入法组合态中不误触；不提供单键直接丢弃代码。右键不是唯一操作入口，拖拽不是唯一分组方式。切换主题、窗口大小和面板开合不能丢失审查位置。

# 06｜仓库与工作区需求

## REPO-01｜打开与识别仓库 · P0
支持选择仓库根目录或其子目录，规范化路径并显示真实工作区。最近项目按本地身份保存；打开失败需区分不是仓库、路径不存在、Git 不可用、权限不足等原因。
**验收：** 从子目录打开与根目录打开指向同一工作区；不得重复创建两份审查状态。

## REPO-02｜工作区身份 · P0
本地仓库 ID 与 worktree ID 分离，同一仓库的多个 worktree 不共享当前 Diff 或当前审查进度。远程 URL 只用于展示，不作为唯一身份；两个独立 clone 不自动合并记录。Git worktree 共享部分仓库信息，但各自有工作树与索引语义。[S5](https://git-scm.com/docs/git-worktree)
**验收：** 同分支名、不同目录、不同 clone 的事件不能串入另一工作区。

## REPO-03｜Git 状态与刷新 · P0
展示未暂存、已暂存、未跟踪、冲突及分支信息。后台状态读取避免不必要的索引锁；文件观察只用于触发刷新，最终以 Git 与文件内容核对。外部 checkout、reset、commit、index 更新均触发重新取数。[S3](https://git-scm.com/docs/git-status)
**验收：** 同一文件同时存在已暂存和未暂存变化时，两者分开显示且比较基准正确。

## REPO-04｜信任与配置 · P0
不自动修改 safe.directory、用户 Git 配置或现有 Git Hooks。不可信仓库先提供受限查看与解释；需要执行 Git Hooks、过滤器或其他配置指定程序时，遵守信任决策。展示当前 Git 可执行文件与版本，允许用户选择。
**验收：** 打开未知仓库不应静默启用仓库指定的可执行扩展或修改全局信任名单。

## REPO-05｜并行与特殊状态 · P0
应用内同一工作区的写操作串行。发生冲突、Rebase / Merge 进行中、无初始提交或 Detached HEAD 时显示明确状态，仅启用已支持的动作。首版可打开已有 worktree，但不提供自动创建 / 删除。
**验收：** 在受限状态点击禁用动作能看到原因，不通过自动 stash、reset 或 abort“修复”。

# 07｜Diff 展示与操作需求

## DIFF-01｜真实比较基准 · P0
未暂存视图比较 index 与工作树；已暂存视图比较 HEAD 与 index；单提交视图比较所选父提交与该提交。新增未跟踪文件单独加载内容，不能因普通 git diff 不包含它而遗漏。比较基准持续可见。[S3](https://git-scm.com/docs/git-status)[S4](https://git-scm.com/docs/git-diff)
**验收：** 每种视图的文件列表与 patch 均可与对应 Git 基准核对。

## DIFF-02｜阅读能力 · P0
提供统一 / 并排、语法高亮、行号、增删行内差异、Hunk 跳转、上下文扩展、文件内搜索、复制所选代码与原始 patch。代码默认只读，编辑通过“在外部编辑器打开”。
**验收：** 隐藏 Context 后可独立完成全部 Diff 阅读与暂存操作。

## DIFF-03｜显示选项与真实内容隔离 · P0
忽略空白、换行显示、软换行仅改变阅读方式，不改变暂存 patch。启用隐藏空白变化时持续提示，并保留真实变化计数；纯空白 Hunk 不得自动视为已审查。
**验收：** 对同一修改切换显示模式，不改变 Git index、文件字节或 Review 证据。

## DIFF-04｜特殊文件 · P0
支持新增、删除、重命名和文件模式变化的明确展示。二进制、LFS 指针、子模块、符号链接、不可解码文件使用专用摘要或原始视图；不以空白页面暗示没有修改，不支持的 Hunk 写操作禁用。
**验收：** 重命名显示新旧路径；删除文件能读到旧内容；二进制不能误走文本 patch。

## DIFF-05｜大文件与并发阅读 · P0
列表虚拟化，按需加载当前文件；超过阈值时默认降级为受控预览并允许主动加载。阅读绑定不可变快照，外部修改只提示更新。选中行和滚动锚点尽量保留，无法定位时解释而非跳到任意位置。
**验收：** 1000 个变化文件场景不一次性创建全部编辑器；旧视图写操作必须重新校验。

## DIFF-06｜编辑器语义边界 · P0
Monaco 等组件只负责展示和文本交互；Git patch 与 Hunk 身份由独立模型维护。编辑器计算出的变化分块不能直接当作可执行 Git patch。
**验收：** 展示分块调整、换算法或折叠上下文后，暂存结果仍是用户选择的真实变化。

# 08｜暂存、丢弃与提交

## GIT-01｜文件与 Hunk 暂存 / 撤销暂存 · P0
动作必须明确作用于哪一侧。执行前校验比较基准和内容指纹；使用真实 patch 及 Git 锁语义执行，完成后重读 index。过滤器或换行转换导致有效内容变化时，以实际 index 预览为准。[S6](https://git-scm.com/docs/git-apply)
**验收：** 只选择一个 Hunk 时不得把另一 Hunk 或同文件后续外部修改一起暂存。

## GIT-02｜安全丢弃 · P0
文件 / Hunk Discard 支持已跟踪的未暂存文本修改与删除；0.1.2 增加多个文件以及 untracked 普通文件（含二进制文件）的 Discard。先展示文件清单并保存每个文件的恢复点，确认后才执行。批量执行前核对完整 Worktree token，每个文件仍单独核对内容；并发写入时停止，已完成的动作与未完成的动作分别报告，不自动覆盖式回滚。untracked 文件从 Worktree 移除但保留原字节，可在路径仍为空时恢复。容量不足、符号链接、重命名等不支持范围明确报错。不会用 git clean 代替所选文件操作。
**验收：** 无法可靠回滚时不执行丢弃；“撤销丢弃”遇到新改动时不得覆盖新内容。

## GIT-03｜提交预览与执行 · P0
普通提交只提交已暂存内容。弹层展示目标分支、已暂存文件、审查覆盖和提交说明；首次明确提示 Git Hooks / 签名可能执行。保留用户已有 Hooks 与签名要求，不自动加 --no-verify。[S7](https://git-scm.com/docs/githooks)
**验收：** 提交失败保留输入；成功后核对实际提交对象和文件集合，不仅依据成功提示。

## GIT-04｜并发写保护 · P0
应用内写操作串行，但不能假装控制外部终端。提交前重新取 index；检测到外部变化要求刷新确认。Git 锁冲突不删除锁、不强杀进程；写后核对实际结果，不符时突出提示，禁止自动 reset 回退。
**验收：** Stage、Commit、Checkout 的并发测试不得静默覆盖用户未选择的代码。仅“预检查通过”不能当作全局原子性证明。

## GIT-05｜基础分支动作 · P0
支持显式创建与切换本地分支。脏工作区、其他 worktree 占用、冲突或操作进行中时展示 Git 原因。切换不隐式 stash、清理或强制覆盖；切换后重新绑定比较基准与审查状态。
**验收：** 用户取消切换或 Git 拒绝切换后，原工作区内容和提交说明草稿不丢失。

## GIT-06｜审查不等于提交许可 · P0
默认允许用户确认后提交未全部审查的内容；提示覆盖范围，不宣称安全。可选“本 GUI 提交前要求审查完成”，只约束本 GUI，不能阻止外部 Agent 或终端提交。
**验收：** 标记 Reviewed 不会自动 Stage；Stage 不会自动 Reviewed；任何状态不自动 Push。

# 09｜人工 Review 与内容版本

## REV-01｜审查单元与状态 · P0
以当前比较基准下的 Hunk 为最小显式审查单元，文件与整个工作区由子项聚合。单元状态为未审查、已审查、待复核；文件可显示部分审查。用户主动标记，不依据停留时长、滚动到底或 AI 结论自动标记。
**验收：** 全文件标记覆盖当前完整变化，包含折叠内容时须明确确认；过滤掉的文件不被悄悄纳入。

## REV-02｜内容绑定与失效 · P0
审查记录包含工作区、比较模式、基准对象、路径 / 文件模式、实际变化与必要上下文指纹、审核时间。行号或 Hunk 序号不能作为唯一身份。内容、上下文或基准无法严格匹配时转为待复核。
**验收：** 在旧代码上标记完成后修改同一段，旧标记不能继续展示为该新内容已审查。

## REV-03｜标记迁移 · P0
仅在变化内容与相关基准可证明一致时迁移标记；纯位置移动可保留，但路径、上下文或 Hunk 拆分 / 合并产生歧义时保守失效。暂存导致比较面变化后，不依据相似文本自动继承。
**验收：** 两段内容相同但位置不同的代码不能互相借用标记；新分支不得继承旧分支的整体完成状态。

## REV-04｜上下文改变的提示 · P0
某 Hunk 文本未变，不代表整个任务仍然验证有效。工作区其他相关文件或基准改变时，显示“工作区已变化，整体结论需重新核对”；保留可核对的局部记录，不显示“全部安全”。
**验收：** 工具能区分“这一段看过”和“当前整组变化已重新核对”，不混用一个绿色徽标。

## REV-05｜进度与专注模式 · P0
支持下一个未审查项、撤销标记、按审查状态过滤和专注阅读。进度同时给出当前范围与全局未审查项；分母是当前快照中的审查单元，不是代码正确率。
**验收：** 过滤已审查文件后，界面不能把可见项全部完成误写为整个工作区完成。

## REV-06｜存储与恢复 · P0
标记原子保存，重启后按最新内容重校验。数据库暂时不可写时，“标记已审查”不得显示为已持久化成功；允许继续看 Diff，但必须提示审查记录保存失败。
**验收：** 进程崩溃后不会出现只保存部分字段、却显示完成的审查记录。

# 10｜Agent 接入、授权与卸载

## OBS-01｜接入必须可选 · P0
设置中按 Agent 列出未配置、已配置待验证、观察中、暂停、受限、不兼容、故障状态。用户选择 Agent、允许的仓库与采集字段后，查看实际配置变更预览再安装。
**验收：** 打开仓库、读取 Diff 或首次启动均不会自动修改 Agent 配置。

## OBS-02｜上游能力检测 · P0
记录 Agent 版本、适配器版本和能力集合；分别检测任务事件、工具事件、结束事件、异步支持和字段可用性。官方文档描述不等于本机已经可用。支持的 Agent / 平台不按精确 CLI 版本设白名单；检测版本用于诊断，兼容性由配置结构、桥接连通和实际事件分别验证。正常 CLI 升级不要求重复安装已有 Hook；程序来源失去信任、权限或配置异常仍停止采集。[S1](https://learn.chatgpt.com/docs/hooks)[S2](https://code.claude.com/docs/en/hooks)
**验收：** 不支持或未知版本不能沿用“已验证”绿灯；缺少某类事件时只降级该能力。

## OBS-03｜不干预配置规范 · P0
仅注册必要观察事件，优先使用经验证的异步 command handler；不使用会返回控制决策的 PreToolUse / PermissionRequest 作为首版依赖。正常处理与可控错误路径保持 stdout、stderr 为空，不输出上下文、工具改写、权限决策或唤醒指令。
**验收：** 适配器夹具与真实 CLI 回归中，不出现本产品新增的模型可见说明、新工具或权限变化。Runtime 可见 Hook 配置不属于缺陷。

## OBS-04｜配置共存与可恢复 · P0
安装程序只增删本产品拥有的条目，保留用户和企业已有 Hook；写前备份，原子更新，检测并发修改，重复安装幂等。配置路径与合并规则由适配器决定，不用一个模板覆盖所有 Agent。
**验收：** 接入 / 卸载前后的配置差异仅限本产品条目；遇到企业策略限制不绕过。

## OBS-05｜验证与卸载 · P0
接入完成先验证桥接连通性；实际事件验证由用户在原终端完成，不擅自启动模型或消耗 token。卸载先移除注册，再清理程序；存在无法清理的注册时提供可执行的恢复说明，避免留下失效路径。
**验收：** GUI 升级、移动安装目录和卸载后，不产生反复的找不到 Hook 程序错误。

# 11｜事件采集与不干预约束

## OBS-06｜有界本地转交 · P0
轻量桥接读取事件并转交本地服务；不执行 Git 扫描、数据库查询、网络模型调用或摘要生成。桥接自带执行期限、输入大小限制及错误恢复；不能仅依赖上游 timeout。重处理在独立采集服务进行。
**验收：** 服务失联、慢读或磁盘满时，不等待 GUI 恢复；资源有上限，故障在 GUI 内记录。

## OBS-07｜异步不是零影响 · P0
上游文档允许异步 Hook，但异步输出仍可能进入后续模型上下文；Claude 的当前文档还说明部分异步运行不由普通 timeout 终止。因此本产品禁止输出反馈，并自行限时。[S1](https://learn.chatgpt.com/docs/hooks)[S2](https://code.claude.com/docs/en/hooks)
**验收：** 无输出、无改写和资源开销分别测试；不得只以 async=true 宣布“完全无感”。

## OBS-08｜丢失、重复与乱序 · P0
事件含来源时间、接收时间、原生标识及可选顺序信息。优先用原生 ID 去重；缺少 ID 不伪造确定性。超限可截断或丢弃，但记录缺口和降级范围；崩溃造成无法量化的缺口标为“完整性未知”，不编造丢失数。
**验收：** 有稳定事件 ID 的重复投递不产生重复活动；缺少 ID 时标注可能重复，不凭猜测删除真实事件。乱序不把后续修改错误标成前一轮结果。

## OBS-09｜生命周期与后台模式 · P0
后台观察默认关闭，由用户显式启用。启用后可独立于窗口运行；“暂停此仓库”“暂停全部”“退出并停止观察”语义清晰。不授予后台权限时，窗口关闭期间的事件允许丢失并提示空档。
**验收：** GUI 崩溃不要求终止 Agent；暂停后新事件不持久化敏感内容，也不偷偷继续收集。

## OBS-10｜正常退出与异常边界 · P0
可控内部失败以中性结果结束；启动失败、进程被系统杀死、损坏配置等不可能由正常退出逻辑完全屏蔽，必须纳入故障演练和兼容性说明。
**验收：** 对外表述是“设计为不干预、已验证低开销”，不是“架构上绝不可能影响 Agent”。

# 12｜会话与 Diff 的关联规则

## CTX-01｜关联顺序 · P0
先识别真实仓库 / worktree，再识别会话、子 Agent 和轮次，最后关联文件变化。原生字段缺失时允许为空；本地生成的 ID 必须标明来源。不能仅凭相同分支名、同一远程地址或接近时间关联。
**验收：** 相邻启动的两个会话、两个 clone 和两个 worktree 均不会串事件。

## CTX-02｜证据级别 · P0
使用“直接关联”“相关会话”“混合修改”“来源未知”四类标签，提供“为何这样标记”。直接关联要求工具负载能指向文件或修改，并且可与捕获内容核对；“相关会话”只表示存在关联线索。
**验收：** 只有文件观察器事件时，来源必须未知；没有编辑器记录时不得把未知写成“人工修改”。

## CTX-03｜异步快照限制 · P0
异步 Post 事件收到时，文件可能已再次变化。此时取得的 git diff 是那个读取时点的整体状态，不是单次工具操作的独占 patch。无法还原可靠前后态时，仅建立会话—文件关联，不建立逐行作者结论。
**验收：** 两个 Agent 先后或同时修改同一文件时，不把最后读取的全文件 diff 都归给最后事件。

## CTX-04｜关联修正与历史 · P0
允许用户手动关联、解除关联并填写本地备注，标注“用户指定”，不篡改原始证据。不自动改 Git author / committer、提交说明、Notes 或仓库内容。
**验收：** 用户修正可撤销；历史记录保留原始关联理由和修正来源。

## CTX-05｜精细归属 · P1
在有可靠工具级 patch、内容快照和无歧义映射时支持 Hunk 级关联。无法满足时继续显示文件级证据。任何归属都不是对法律作者身份、代码原创性或企业审计的证明。
**验收：** 精细归属只有在真值测试集达到发布门槛时启用；不得靠模型“猜是谁写的”。

# 13｜Context 与命令 / 测试证据

## EVD-01｜Context Inspector · P0
固定结构为任务原文、来源与关联理由、相关事件、命令 / 验证记录、最终回复。原文与分析内容视觉区分。未授权采集某字段时显示“未开启记录”，不写成“Agent 没有执行”。
**验收：** 从当前文件或 Hunk 可打开有关会话；无关全量聊天不挤占默认面板。

## EVD-02｜命令证据 · P0
保存允许范围内的命令、工作目录、开始 / 结束时间、退出状态、截断标记及工具调用引用。复合 shell 命令只说明可观察的整体状态，不能推断每个子命令成功。首版只观察，不自动重跑命令。
**验收：** 命令尚在执行、结果缺失与 exit 0 分别显示；未知退出状态不得显示成功。

## EVD-03｜测试状态 · P0
区分“命令成功”“结构化测试通过”“Agent 声称通过”“未观察到结果”。只有有效结构化报告才显示具体用例数量；单凭 go test、npm test 字符串或自然语言不能生成精确测试计数。
**验收：** 同一场景中只有 Agent 最终回复声称通过时，不能出现“已验证通过”的绿色汇总。

## EVD-04｜验证与代码版本 · P0
测试记录关联可取得的代码快照、基准与运行时间。仅在开始、结束及输入范围可核对时标为对应快照；只拿到 Post 结果时默认版本关系未确认。运行期间或之后有相关变化时标记过期或不确定。
**验收：** 测试后再次修改代码，旧结果不会被展示为当前快照已经验证。

## EVD-05｜完整性与缺失说明 · P0
上下文完整性、修改归属、审查状态和验证状态四套维度独立展示。完整性包含采集中断、超限截断、字段未提供、字段未授权及原始证据已清理。
**验收：** “来源直接关联”不能自动提升测试可信度；丢失采集数据不会让原始 Diff 消失。

# 14｜AI Change Grouping 与 AI-assisted Review · 核心功能

## AI-01｜逻辑变更分组 · P0
用户点击 **AI Group Changes** 后，以当前 Local changes 的固定 Git Diff 为输入，按逻辑变更自动生成文件分组。例如 Authentication 包含 auth.go / token.go，Connection Pool 包含 pool.go / pool_test.go。
每组返回结构化 title、summary、files、risk、reviewPriority。每个 changed path 恰好属于一个组；同一路径的 Staged / Unstaged Diff 保留各自版本与状态。首版以文件为分组单位，Hunk 跨组留待后续独立需求。
用户可改名、把文件移动到其他组 / 新组、取消单个分组或 Ungroup all。没有现有分组时自动应用本次结果；已有分组时提供 Apply groups。分组使用版本校验，运行期间的手动编辑不会被迟到结果覆盖。
**验收：** 未知路径、重复文件、遗漏文件、无效风险 / 优先级均拒绝；分组仅写 Proof 元数据，不改变 index、提交边界、源文件或人工 Reviewed 状态。没有 Agent 仍可人工分组并使用 Files / Tree。

历史 Diff 同样提供 AI Change Grouping，输入为当前 tab 固定的 base / target Commit，分组与 Local changes 分开保存。用户可在两个范围中使用相同的改名、移动文件和取消分组操作。Review Current Change 覆盖当前分组内的比较文件；仅在用户点击后调用 CLI。

## AI-02｜AI-assisted Review · P0
提供 **Review All Changes** 和 **Review Current Change**。Local changes 中 Current 指当前文件所在的 Change group，未分组时为当前文件；独立 Diff tab 中 Current 同样对应当前 Change group，未分组时为当前文件；All 指该 tab 固定的两个 Commit 之间全部 Diff。
结构化结果包含 Summary、Overall Risk、Findings、Behavior Changes、Missing Tests、Review Priority。Finding 必须含 severity、title、description、file、line（起始行）、endLine（结束行，包含边界）、suggestion，另带 Staged / Unstaged 和 old / new 行侧，避免删除行和部分暂存的歧义。点击后打开对应文件并定位、突出显示原始 Diff 行范围。评论气泡出现在对应范围下方，可折叠；每条 Finding 可选择采纳、不采纳，并可撤销回待处理。采纳仅记录处理意向，不自动修改代码，也不代表问题已修复或已人工 Reviewed。
结果绑定输入快照、比较范围、生成时间和 Provider。Local changes 的版本或比较 OID 不匹配时明确显示过期并禁用旧定位；用户主动重新 Review。AI 不将任何 Hunk 标为 Reviewed；无 Findings 不等于正确或测试通过。
主动分析输出必须携带 analysisStatus 与 blockers。读取工具失效或快照无法读取时返回 blocked，界面显示分析受阻，后端不将其保存成空 Findings 的成功报告，也不应用分组；CLI 退出成功不足以证明分析完成。
**验收：** 每个 Finding 的起止行及区间内每一行必须在捕获的相同行侧 Diff 中验证，不得跨越未提供的上下文；不支持、空、截断、错误格式或失败输出不产生虚构的通过结论。结果与逐条处理状态保存到 Proof 本地 SQLite，退出重启后恢复，Review history 可切换此前报告。Local changes 与冻结的 base / target 分开保存；沿用 Review 记录 180 天保留期，并随仓库本地数据删除清理。不写入 Passive Observer 会话。

**交给 Agent 修改：** AI Review 提供“导出给 Agent”。默认选择已采纳意见，用户可调整本次导出的选择、预览修改说明、一键复制或通过原生保存对话框保存 Markdown。说明包含 Worktree、当前 Branch、Review 时间、Provider、文件路径、引用版本及起止行、问题和建议；历史 Diff 必须保留完整 base / target OID，不能把历史比较误表述为当前未提交变化。过期报告可导出，但必须注明重新核对代码与位置。仅导出所选 Findings，不把报告内其他建议隐式变成修改任务。导出不调用模型、不改变采纳状态、人工 Reviewed 或 Git 状态。单栏和并排 Diff 中，评论滚出视口再返回时必须恢复；隐藏评论产生的零尺寸不能清除其占位。

## AI-03｜本机 Coding Agent Provider · P0
统一 AgentAdapter 能力登记，列出每个 Agent 的主动 Provider、程序发现与被动 Hook 接入能力；主动调用实现 CodexProvider、ClaudeCodeProvider 和 CodewizProvider。Proof 不接 OpenAI / Anthropic / Gemini 模型 API，不保存 / 要求 API Key，也不安装或内置 Agent。仅在用户主动点击后启动本机已安装、已登录的 Codex CLI / Claude Code，使用其正常登录及额度；界面在动作旁说明 Diff 会交给所选 CLI。
Settings → AI Agents 提供默认 Provider、CLI 路径、可选模型和 Test CLI。自动发现仅检查程序位置；用户点击 Test CLI 后检查版本、只读参数和本地登录状态，不启动模型。设置仅保存在 Proof，不修改 CLI 全局配置；实际运行前检查隔离参数支持，不限制固定 CLI 版本，缺失能力时列出具体参数。新任务不 resume / continue / attach 用户原 Session，不改变任何全局 CLI 配置。取消只结束 Proof 所拥有的进程组。
**验收：** CLI 缺失、未登录、额度不足、版本不兼容、超时及用户取消均不影响 Git、Diff、Stage、Commit 和人工 Review。主动 AI 与 Passive Agent Observer 的安装、授权、生命周期、存储完全独立。

Settings 还提供 Grouping、Review、Commit 三类独立自定义 Prompt，支持恢复默认、跨重启保存。Prompt 控制语言、风格和任务重点，不能改变只读边界和结构化数据校验。保存设置不启动模型。

主动任务每次新建会话，并保留到对应 Agent 的原生会话存储。关闭或完成任务不再主动禁止原生会话持久化；不接续或覆盖用户已有 Session。结果可复制 CLI 恢复命令；不同 CLI 的非交互会话遵循各自列表 / Session ID 恢复规则。清除 Proof 本地数据不删除 Agent 管理的原生会话。

## AI-04｜只读执行与数据边界 · P0
代码、注释、路径和 Patch 均为不可信数据，不能改变只读任务权限。Review 与 Grouping 的 CLI 工作目录直接指向当前真实项目目录，Agent 可以按需搜索完整实现、调用方、测试、文档与配置；不复制项目，不因 ignored、大文件或上下文数量而裁剪可读目录。任务范围决定哪些变更需要分析，不限制为理解它们而读取项目内其他文件。被动 Observer 会话不作为主动分析输入。
Proof 通过 stdin 提供任务说明、范围和输出 Schema，并在独立临时目录保存范围清单与 canonical Git patches，作为定位和校验结果的辅助证据。这些 Patch 冻结本次选定 Diff，不替代完整项目上下文。Local 区分 HEAD / Index / Worktree；Agent 可以使用只读 git show / diff / log 查询对应版本。历史比较固定 base / target OID（支持根 Commit 的 empty base），不能将当前 Worktree 当成历史版本。项目文件实时可见，结果注明实时上下文可能变化；Diff 版本不匹配时沿用过期标记和定位保护。
macOS 使用进程级只读沙箱，CLI 及所有子进程仅能写本次私有运行目录，不能写辅助证据、源仓库、Git、其他 Session 或全局配置，也不能发送外部进程信号。允许受控的文件读取、搜索和 Git 查询程序，主动调用禁用用户 Hooks、MCP、Plugins、浏览器和其他扩展；Git 查询关闭 fsmonitor、Git Hooks 和可选 Index 写入。保留模型所需 Code Mode host，验证同安装目录来源。正常 CLI 登录和独立运行目录沿用既有实现，不要求 API Key，不 resume / attach 用户 Session。
辅助 Diff 证据保留本机资源保护：最多 20,000 个文件侧、128 MiB canonical patches；现有单文件 Diff 读取上限继续适用。取消原项目快照的 256 MiB / 100,000 路径 / 单文件 4 MiB 上下文复制限制。CLI 流式输出有 32 MiB 上限，推理没有固定时限，直到 Agent 完成或用户主动取消。stderr 不保存原始内容，错误摘要仍脱敏和限长。工具无法读取必需内容时返回 blocked，不能把缺失上下文解释为审查通过。
**验收：** 故障夹具尝试改源文件、index / HEAD、其他 Agent Session 和发送终止信号均失败；超时 / 取消不遗留进程；删除 Proof 本地数据后迟到结果不能重新写入分组。

## AI-05｜UI 与来源真值 · P0
保持 **Files / Change groups | Diff | Context / AI Review**。中央 Diff 占主要区域；左侧提供文件树和逻辑分组切换，右侧用结构化报告和定位动作，不做聊天框。历史范围比较继续使用独立 Diff tab。
Git Diff 永远是 Source of Truth；AI 分组、风险与解释仅为辅助，最终 Review 由人完成。AI Commit、生成代码或 Agent 自称完成均不构成人工 Reviewed。

## AI-06｜主动任务活动与取消 · P0
Grouping、Review、AI Commit、独立 Diff tab 共用活动面板，显示准备变更 / 快照、启动 Agent、读取文件、搜索代码、Git 查询、执行命令和校验结果等实际阶段。仅在已知文件路径匹配时显示路径，不显示内部推理、原始命令参数、工具输出和凭据。捕获阶段可显示真实文件计数；Agent 探索期间不伪造百分比。
始终显示运行时长。连续 15 秒没有新事件时提示等待新活动，不能将无事件直接判为卡死或失败。最近 40 条活动有界保留，重复准备事件合并；活动可展开查看。取消后显示正在取消，终止本任务所拥有的进程组，完成或失败后结束运行状态。事件按窗口和一次性读取 ticket 隔离，监听先于任务注册，结束后解除监听；旧任务和其他窗口事件不能更新当前任务。


## AI-07｜AI Commit message · P0

Commit 页显式触发 AI Commit，仅根据当前 Staged 变更生成可编辑的提交说明。Amend 时结合上一条 Commit 和 Staged 增量；普通模式未 Stage 时提示先选择提交内容。支持本机 Codex、Claude Code、已安装 Codewiz、活动提示、取消与错误详情。已有草稿保持原样，用户选择采纳后替换；生成期间 Index / HEAD 改变则拒绝应用旧结果。AI 不执行 Stage、Commit、Amend、Push 或人工 Reviewed 操作。

**验收：** 生成操作不改变 HEAD / Index；不会把 Unstaged 内容当成 Staged；不会覆盖生成期间输入的草稿；缺少 CLI 时普通 Commit 不受影响；三类 Prompt 各自保存和生效，设置更改不消耗 Token。


# 15｜Repository 页面与传统 Git 能力

## HIS-01｜提交历史 · P0
提供分页提交列表、作者、时间、分支引用、说明搜索和选中提交 Diff。Merge commit 需显示父提交选择；默认与第一父提交比较时明确说明，不将其伪装为全部合并语义。
**验收：** 大历史不一次加载所有对象；所选提交与比较基准始终可见。

## HIS-02｜文件历史与 Blame · P0
从 Diff 进入基础文件历史与指定版本 Blame。未提交新增行显示“未提交变化”，不伪造作者；重命名追溯不能确定时提示局限。Agent 观察记录单独展示，不覆盖 Git 历史作者。
**验收：** 点击历史返回当前 Changes 后，恢复原文件、滚动位置和审查状态。

## HIS-03｜分支与工作区列表 · P0
列出本地分支、远程引用及已有 worktree；显示当前路径与脏状态。未 fetch 时，远程引用与 ahead / behind 只能代表本地已知状态，需标注最后已知更新时间。
**验收：** 不能把本地缓存写成“远端实时无变化”。首版不后台执行 fetch。

## HIS-04｜不支持的操作 · P0
在 Merge / Rebase 等进行中状态给出解释、原始 Git 输出和外部终端入口，不自动执行恢复。复制命令仅是复制，不等于执行；打开终端仅打开相应目录，不附带破坏性命令。
**验收：** 任何高级 Git 能力缺失都不会触发静默 reset、stash 或自动解决冲突。

## 后续边界
完整 Commit Graph、远程交互、Stash、交互式 Rebase、Cherry-pick、冲突编辑和 PR / MR Review 分批进入 P1 / P2。每个 Git 写能力须单独补充并发、凭据、签名、Hook 和失败恢复验收，不因已有 CLI 就视为完成。

# 16｜设置、导出与诊断

## SET-01｜设置层级 · P0
设置分应用级与仓库级；仓库覆盖值有明确标记。提供主题、语言、字体缩放、Diff 偏好、外部编辑器、Git 路径、观察配置、存储保留和快捷键。首版中文优先，同时保留必要 Git 术语。
**验收：** 恢复 UI 默认设置不删除仓库、Agent 配置、Git 配置或审查记录。

## SET-02｜数据管理 · P0
按仓库查看存储用量、清理记录、停止观察、移除最近项目和彻底删除本产品记录。每种动作说明是否删除本地数据；任何操作不删除源仓库、不改原 Agent 历史。
**验收：** 删除仓库观察数据后，重启不能从索引或缓存恢复被删内容；外部备份副本需另行说明。

## SET-03｜诊断导出 · P0
提供适配器版本、能力检测、错误码、队列状态和性能摘要的预览导出。默认排除源码、prompt、原始命令输出、绝对路径、远程 URL 和凭据；主动勾选额外内容时逐类确认。
**验收：** 可在无网环境导出；用户可检查并取消，不自动上传给开发团队。

## SET-04｜审查报告与证据导出 · P1
导出 Markdown / JSON，可选 patch；说明快照、比较基准、已审查范围、来源标签和验证时效。不包含隐藏思考或“代码绝对安全”结论。默认不包含任务全文和原始输出，导出前预览与脱敏。
**验收：** 分享者知道哪些本地数据将被复制；导出报告的旧状态不会伪装成实时结果。

## SET-05｜可解释错误 · P0
错误至少包含发生动作、影响范围、当前保留状态、可安全采取的下一步和可复制错误码。持续错误聚合，避免每次事件弹窗；重要写操作失败不能只写入后台日志。
**验收：** 用户可区分 Git 错误、观察错误与本地存储错误，且不会被诱导一键删除锁文件。

# 17｜核心数据模型

## 17.1 本地实体与关系
| 实体 | 关键字段与约束 |
| --- | --- |
| Repository / Worktree | 本地 UUID、规范化路径、common git dir、独立 git dir、checkout_epoch；不以远程 URL 唯一标识 |
| Snapshot | worktree_id、比较模式、基准对象及 hash 算法、index 指纹、捕获时间、稳定性标记 |
| FileVersion / ChangeUnit | 路径、旧新路径、文件模式、字节指纹、编码 / 换行信息、原始 patch、显示分块引用 |
| ReviewMark | change_unit_id、比较面与内容指纹、状态、时间、显式用户动作、失效原因 |
| AgentSession / Turn | Agent 与适配器版本、原生 session / turn / subagent 标识、可空字段、状态、关联工作区 |
| AgentEvent | event_id、原生 ID、事件 / 接收时间、工具引用、裁剪字段、截断 / 丢失状态、schema_version |
| EvidenceLink | 事件与文件 / Hunk / Snapshot 的关联、证据类型、理由、人工修正记录 |
| ValidationRun | 命令状态、结构化报告、开始 / 结束时间、快照绑定质量、过期原因 |
| ChangeGroup / Analysis | P0；文件引用、分组版本、生成快照、Provider、结构化 Findings；与人工 Review 分离 |
| RecoveryPoint / Operation | 显式写操作、预期 / 实际基准、恢复内容、过期时间、操作结果 |

## 17.2 数据一致性要求
内容指纹用于判断当前记录适用性，不把 Git 对象 ID 强制假定为固定长度 SHA-1。文件字节、Git 有效内容和渲染文本分别建模，避免换行规范化造成误匹配。Review 与证据索引事务写入；GUI 使用版本化响应，旧请求结果不能覆盖新工作区。

## 17.3 数据边界
本地观察库与源仓库隔离，默认不写 .git 或仓库目录。源码快照仅为已打开 Diff、明确审查或可恢复写操作所需，不以观察为理由复制全仓库。Hash 不是匿名化承诺，仍按本地敏感元数据管理。

# 18｜状态机与关键业务规则

## 18.1 人工审查状态
| 当前状态 | 触发条件 | 新状态 / 处理 |
| --- | --- | --- |
| 未审查 | 用户对当前内容明确标记 | 已审查；保存内容与比较基准 |
| 已审查 | 同单元内容 / 相关上下文 / 基准变化 | 待复核；保留旧记录，不给新代码背书 |
| 已审查 | 仅位置变化且可严格重定位 | 可保留局部标记；不能提升整组结论 |
| 待复核 | 用户打开当前版本并重新标记 | 已审查；新记录关联新快照 |
| 任意状态 | Hunk 消失或变化已提交 | 退出当前进度分母；旧记录保留为历史 |
| 任意状态 | 数据丢失 / 无法重定位 | 未审查或待复核；不自动恢复完成状态 |

## 18.2 会话状态
“最近有活动”是观察结果，不等于精确运行状态。仅有明确开始 / 结束事件时显示开始 / 结束；长时间无事件显示“暂未收到活动”，不自动宣布完成或卡死。会话结束、Agent 一轮回复结束和工具结束分别建模。

## 18.3 验证状态
运行中 → 已观察命令成功 / 失败 / 结果未知；存在有效报告时追加结构化测试结果。快照关系单列为匹配、过期、运行期间变化、无法确认。以上状态不因 Hunk 被暂存而自动提升。

## 18.4 并发与观察空档
应用无法暂停或锁定外部 Agent 来换取精确归属。检测到连续写入时允许继续阅读稳定快照，暂存 / 丢弃 / 提交需刷新或再次确认。缺少开始快照或存在观察空档时，来源与验证关系按实际证据降级。

## 18.5 业务不变量
Review 不自动 Stage；Stage 不自动 Review；Commit 不自动 Push；Agent 完成不等于任务完成；命令成功不等于测试通过；测试通过不等于代码正确；会话相关不等于独占作者；模型分析不等于观察事实。

# 20｜安全、信任与不干预验收

## SEC-01｜Agent 与观察通道 · P0
默认使用同用户本地 IPC；Unix socket 限制权限，Windows named pipe 限制访问主体。接收端校验来源、消息长度、schema、允许仓库与路径。默认不开放远程 HTTP 接口，localhost 本身不能当作充分认证。

## SEC-02｜最小能力与代码执行 · P0
前端不调用任意 shell；Git 参数结构化传递，路径与选项分离，校验越界与符号链接。Markdown / 日志 / 源码按不可信内容渲染，不执行脚本、加载远程图片或自动打开链接。打开外部编辑器需用户动作与允许配置。

## SEC-03｜配置权限边界 · P0
不修改 AGENTS.md、CLAUDE.md、工具列表、MCP 配置、Agent 系统提示或权限策略；不安装控制 Agent 的 Skill。保留现有安全 Hook。观察模块无“回传 prompt / 改写工具 / 审批调用”产品接口，但仍需承认本地可执行程序不是形式化不可写沙箱。

## SEC-04｜更新与供应链 · P0
发布包、更新及桥接版本可校验，升级后重新做能力检测；失败可回退兼容版本。敏感数据不出现在进程命令行、崩溃上报、安装日志或下载 URL 中。只从受信发布渠道安装，不执行仓库提供的 Hook 程序替代本产品桥接。

## SEC-05｜验证方式 · P0
采用确定性工具调用夹具检查输出字节、配置差异与写文件行为；在支持的真实 CLI 做端到端回归。可取得请求轨迹时核对模型输入及工具 schema；无法取得时只报告已验证范围，不宣称证明“token 完全不变”。

## 威胁模型边界
防范误操作、配置冲突、恶意仓库内容、跨仓库串数据、无权限本地客户端、敏感信息误外发和失控采集。拥有同一用户权限的恶意程序、已被攻破的操作系统及外部备份复制不在单个 GUI 能彻底防御的范围内，不能宣称防篡改审计系统。

# 21｜隐私、采集等级与保留策略

## 21.1 采集等级
| 等级 | 默认行为 | 需要的授权 |
| --- | --- | --- |
| L0：关闭 | 不注册 / 不持久化 Agent 活动；Git 正常使用 | 无 Agent 授权 |
| L1：基础观察 | Agent / 会话标识、允许仓库内相对路径、工具名称、时间与退出状态 | 用户选择 Agent 与仓库后开启 |
| L2：任务上下文 | 在 L1 上增加任务说明、允许的命令字段与结果摘要 | 按字段显式勾选；不自动采集完整聊天 |
| L3：扩展证据 | 有界原始输出、历史会话导入等增强 | 单独授权；首版不提供全量 transcript 导入 |

Hook 可能先收到包含敏感字段的上游负载；产品保证的是按授权筛选持久化和外发，不虚称这些字段从未进入进程内存。脱敏是降低风险的辅助措施，不能保证识别所有秘密。

## 21.2 拟定默认保留
| 数据 | 默认期限 / 上限 | 清理行为 |
| --- | --- | --- |
| 规范化观察元数据与已授权任务 | 30 天 | 到期删除；失去证据的链接标明原因 |
| 已授权命令输出摘要 | 7 天；每事件持久化文本不超过 64 KiB | 截断显式标记；不落无限日志 |
| Review 报告、处理状态、人工标记与操作元数据 | 180 天，可按仓库清理 | 重校验适用性，不自动补造原始证据 |
| 丢弃恢复点 | 7 天或总计 256 MiB，先到者生效 | 丢弃前提示可恢复范围；恢复点满时不静默失去保护 |
| 全应用数据 | 2 GiB 拟定软上限 | 先清可重建缓存 / 到期记录；仍超限则暂停内容采集并提示 |

## 21.3 本地保护与删除
默认采用用户级文件权限；SQLite 本身不构成加密承诺。依赖系统全盘加密的保护需说明前提；模型密钥等进入系统凭据设施。删除覆盖数据库行、搜索索引、内容文件、应用缓存及本产品备份；不能承诺擦除操作系统快照或用户自行导出的副本。

## 21.4 网络默认值
核心审查无网络要求；不默认自动 fetch、模型调用、上传诊断或使用统计。应用更新检查可独立关闭。未来用户主动执行远程 Git 或授权 AI 外发时，分别说明目的、目标和数据范围。

# 22｜非功能要求与性能预算

## 22.1 测试基线
以下是待实测的目标，不是现有性能声明。参考机器为 Apple Silicon、16 GiB 内存、本地 SSD；Windows 用同等级独立基线。固定发布构建、Git / Agent 版本和电源状态；至少 30 次重复，报告 P50 / P95 及进程树资源。

标准仓库：1 万已跟踪文件、10 万提交、100 个变化文件、1 万行累计文本 diff；单文件不超过 1 MiB。压力仓库：10 万文件、100 万提交、1000 个变化文件、10 万行累计 diff。合成夹具必须包含未跟踪、重命名和混合暂存状态。

## 22.2 拟定预算
| 编号 | 指标 | P0 拟定目标 |
| --- | --- | --- |
| NFR-01 | 冷启动至可操作；不含系统权限交互 | P95 ≤ 3 秒 |
| NFR-02 | 标准仓库首批 Changes 可用 | P95 ≤ 2 秒；其余渐进加载 |
| NFR-03 | 已获取文件的 Diff 切换 | 缓存 P95 ≤ 100 ms；未缓存 ≤ 500 ms |
| NFR-04 | 标准本地 Stage / Unstage | P95 ≤ 500 ms；不含用户过滤器异常耗时 |
| NFR-05 | 普通事件在 Context 可见 | 接收后 P95 ≤ 1 秒；拥塞显示延迟 |
| NFR-06 | 桥接附加开销 | ≤64 KiB 事件下，P95 目标 ≤20 ms；客户端自身期限目标 50 ms |

## 22.3 可靠性与可用性
桥接耗时与 CLI 主路径增量分别报告，不把模型 / 网络波动算作桥接耗时。超大文件默认先展示摘要，用户主动加载；压力场景禁用昂贵高亮但保留原始内容入口。读取取消与过期请求去重；观察异常不拖垮 Git 阅读。审查 / UI 持久化失败必须可见。无障碍以键盘可完成、焦点可见、非纯颜色表达及文本缩放可用为验收，不未经审计宣称符合完整标准。

# 23｜产品指标与验证计划

## 23.1 北极星候选
**每周完成的有效人工审查会话数。** 一次有效会话要求：在明确快照中主动审查至少一个变化单元，并发生暂存、提交或明确结束审查之一；只打开应用、自动刷新或 AI 输出不计入。该指标用于观察使用行为，不等于代码安全性。

## 23.2 指标与拟定判断标准
| 指标 | 定义 | 初始目标 / 护栏 |
| --- | --- | --- |
| 首次任务成功率 | 无帮助完成打开仓库—Diff—暂存—提交的比例 | 可用性测试 ≥90% |
| 上下文定位效率 | 从一个 Hunk 找到有关任务 / 证据的时间 | 对照原终端翻记录，中位数减少 ≥20% |
| 审查有效性 | 预置缺陷中被参与者正确发现的比例 | 不低于只看 Diff 的基线，不以提速换漏检 |
| 状态可信度 | 人工改动后的错误保留审查标记次数 | 发布固定真值测试集为 0 |
| 关联精确度 | 被标为“直接关联”的条目中真正正确的比例 | 固定真值测试集为 100%；覆盖率单独报告 |
| 接入可靠性 | 已支持组合中完成配置且收到真实事件的比例 | 兼容性回归全部通过；未知版本不计为支持 |
| 非干预护栏 | 本产品造成控制输出、权限变化、无限等待 | 支持矩阵的故障注入测试为 0 |

“固定测试集为 100%”是发布门槛，不是对任意真实环境的零错误保证。宁可降低精细关联覆盖率，也不为提高指标制造错误确定性。

## 23.3 用户验证方法
招募约 8—12 名符合 U1—U3 的开发者，采用交叉顺序任务，覆盖纯 Git、Agent 证据完整和证据缺失。记录完成时间、误暂存、漏检、状态理解和主观负担。首次样本只用于方向判断，不作为市场规模或普遍生产力提升证明。

## 23.4 测量与隐私
默认仅保存用户本地的非内容性能与动作计数；不采集源码、任务全文、仓库名或命令内容做产品统计。参与研究或发送诊断均显式同意，可撤回。商业化、账号体系与收费不纳入 v0.1 决策。

| Git 锁 / 写操作失败 | 动作、影响、保留状态、错误详情 | 刷新或稍后重试；不提供一键删锁 |
| 存储不可写 | 持续状态提示而非成功 Toast | 继续只读；导出诊断 / 管理空间 |

## 29.2 快捷键提案
Command / Ctrl+K 打开命令面板；Command / Ctrl+P 搜索变化文件；Alt+下 / 上切换 Hunk；Command / Ctrl+Shift+R 进入专注审查。标记、暂存提供可配置组合键，不默认复用编辑器常见单键。提交快捷键只打开预览，不直接执行提交。Esc 关闭浮层或退出专注模式，不撤销已持久化动作。

## 31.1 术语
| 术语 | 本产品中的含义 |
| --- | --- |

## Diff workspace 补充（2026-09-14）

Local changes 和历史 Diff 复用文件栏、分组、可收起 / 拖动的侧栏与中央阅读组件。提供 Open in Window，历史窗口保留不可变比较 OID，本地窗口实时更新。窗口独立拥有监听和取消票据，关闭一个窗口不影响其他窗口。语法高亮按语言解析，并与搜索、行内 Diff 同时显示；大文件保留原文和有界降级。验收包括范围隔离、分组持久化、键盘操作、窗口请求和数据清理广播。详见 DIFF-WORKSPACE.md。

### Diff 加载稳定性
Local changes 与历史 Diff 使用同一加载层，固定在中央阅读区内。切换文件时不得插入额外布局行或改变两侧栏、中央面板的尺寸；尚未读取的文件显示路径与占位内容，不能继续操作上一文件。刷新同一文件时保留已显示内容、禁用写操作，并在区内显示更新与取消读取按钮。

## SET-04｜界面语言 · P0

提供简体中文与 English，在设置的外观与阅读中切换。现有用户默认保持简体中文；语言设置保存于 Proof 本机数据库，退出后保留，多窗口同步。切换立即生效，不清空 Commit 草稿、文件选择、Diff tabs 或阅读状态。

中文界面的普通按钮、提示、错误说明和无障碍标签统一用中文；Git、History、Commit、Review、Diff、Branch、Worktree、Stage 等术语保留英文。日期与数字使用所选语言格式。macOS 菜单跟随同一语言设置。

**验收：** 切换、重启恢复、保存失败回退与多窗口同步有回归覆盖；语言设置不会被另一窗口的阅读偏好覆盖。两份文案目录保持键与插值参数一致，Git 内容不因语言变化而改变。详见 `I18N.md`。

## BG-01｜后台刷新 · P0

进入 History、History 回到前台时，对已信任且有 remote 的仓库自动 fetch。按共享 Git 仓库限制至少 60 秒一次，跨窗口与 Worktree 共用限频，失败也计入间隔，不允许重叠。仅更新远程引用，不改变 HEAD、Index、Worktree 或手动 Fetch 的 FETCH_HEAD，不运行 Hook / submodule / 自动维护，不弹出凭证交互。网络过程不占用 Diff 读取锁；离线保持本地历史可读，手动 Fetch 仍保留完整反馈。

Local Changes 通过文件监听自动刷新，监听不可用时静默转为轮询；切回 Local Changes / Commit 或窗口恢复前台立即核对本地状态。后台刷新保留当前文件、可读 Diff 和滚动位置，不显示通知或加载浮层；临时失败自动重试。持续读取失败只在底部状态标记，不覆盖用户主动操作的错误。History 更新保留选择与视口，只有切换仓库或历史范围才重置。

## HG-01｜History Git 操作 · P0

History 工具栏提供 Fetch / Pull / Push 和创建 Branch。Branch 侧栏与图中标签共用菜单，提供 Switch、创建 Branch、Merge 到当前 Branch、将当前 Branch Rebase 到目标、重命名、删除、复制 Branch 名称与比较。远程 Branch 可创建本地 tracking Branch 并 Switch。右键之外提供可见的更多操作按钮及键盘导航。

Commit 菜单提供 Detached checkout、创建 Branch / Tag、Cherry-pick、Revert、Rebase、Reset soft / mixed / hard、复制完整 SHA / Commit message。Merge Commit 的 Cherry-pick / Revert 明确选择 Mainline Parent。比较继续在独立 Diff tab 展示。

Pull 明确选择 Remote、远程 Branch 与 fast-forward-only / Merge / Rebase，默认 fast-forward-only。Push 显示明确目标，仅推送所选 Branch；不隐式 force、mirror 或推送额外 refs。沿用用户现有 Git 登录方式，不收集 API Key，不调用 Agent，不自动执行网络操作。

所有写操作先校验信任和当前 Git 状态，显示目标与影响；Rebase、Reset、Abort 要求确认改写或丢弃影响。执行前再次校验 HEAD / Branch、目标引用、Worktree / Index、配置与 Git 流程状态。过期预览停止，Git 失败不自动重试或回滚。执行后显示实际结果并刷新 History 与 Local changes。

Merge / Rebase / Cherry-pick / Revert / Pull 前需先处理本地修改，不自动 Stash。冲突时提供逐文件 Stage 解决结果、Continue 与 Abort。Stage 解决结果表示用户确认文件已在编辑器中处理，不表示 AI Review 或人工 Review 已完成。

**验收：** 临时真实仓库覆盖成功、分叉、冲突、登录/远程失败、过期预览、多 Worktree 与未合并 Branch 保护；UI 覆盖工具栏、右键/键盘菜单、复制、切换/重命名、执行后刷新、冲突继续和 Reset 确认。详见 `HISTORY-ACTIONS.md`。


## UI-07｜统一组件与代码阅读 · P0

Local changes 和历史 Diff 复用同一 Files / Change groups、Diff、Context / AI Review 工作区。基础按钮、字段、菜单、弹窗、提示和通知使用共享组件；视觉参数来自 Tailwind 语义令牌，不在每个页面分别设计。

文本 Diff 使用只读 Monaco；统一和并排视图均映射 Git 原始行号。Hunk 操作与行范围 Review 留在代码区，气泡支持采纳、不采纳和撤销。全文、上下文增减、空白筛选与搜索只改变阅读范围，不能改变 Git Patch。二进制、符号链接、Submodule、特殊文本或编辑器加载失败时保留可用的专用/简化阅读器。大型 Diff 继续按需加载。

用户可拖动调整侧栏宽度、排列 Diff tabs、在逻辑分组之间移动文件，并保留键盘或菜单操作。固定导航页不参与 Diff tab 排序。分组拖动仅修改 Proof 的分组记录；过期快照或分组修订冲突必须拒绝覆盖。

**验收：** 切换文件、tab、明暗主题和全文范围时保持布局与源代码位置；Review 气泡不会因高度测量反复重建；模态窗口和菜单支持 Escape、焦点恢复和键盘选择。Monaco 与 Worker 随应用本地打包，离线可用。尺寸适配不覆盖用户保存的宽度；关闭/隐藏大型阅读器后释放文本模型。详见 `UI-MIGRATION.md`。

## GIT-12｜日常 Git 操作入口 · 0.1.2

工作区布局补充：仓库、Branch 与页面 / Diff tabs 合并为一条标题栏；文件树采用 32px 行高和 20px 层级缩进，默认宽度 320px，已有自定义宽度保留。普通点击查看 Diff，勾选或修饰键用于多选，固定底栏承载批量操作。Commit 页以左侧文件树与提交说明、右侧共享 Diff 组成；切换到 Local changes 保持同一阅读器和当前文件。History 图中的 Branch 标签与同一 Commit 行右键使用统一菜单，明确当前 Branch 与 Commit 操作目标。

- Git 工具栏位于 History 内部，提供 Fetch、Pull、Push、创建 Branch、Stash 与 Discard 恢复点。全局标题栏、Local Changes、Commit 和 Diff 不占用这排工具栏。使用同一个操作控制器和预览确认框；进行中的动作不能重复执行。
- 当前 Branch 旁有可见的操作菜单；分支下拉列表、History Branch 列表共用 Switch、Merge、Rebase、Rename、Delete、Push、复制 Branch 名称、完整 Ref 与 Commit SHA。Push 可以指定其他本地 Branch，无需先 Switch；预填该 Branch 自己的 upstream，预览清楚显示本地来源和远程目标。默认普通 Push，拒绝 non-fast-forward；Push 对话框可主动选择 Force Push with Lease。预览从实际 Push URL 读取并固定远程 Branch 的 Commit，显示本地来源、远程目标与预期 Commit，确认后只对该 Branch 执行显式 lease；远程变化时拒绝推送，后台 Fetch 不得悄悄推进已确认的 lease，不提供无条件 Force Push。
- 文件树、文件列表与 AI Change Groups 共享文件操作菜单；提供 Stage / Unstage、Discard、相对路径 / 绝对路径 / 文件名复制以及恢复点入口。文件树支持多选和目录范围，菜单始终显示实际文件范围。历史 Diff 仅提供复制等只读动作。
- Stash 管理支持保存（可选说明、可选包含 untracked）、Apply、Pop、Drop；恢复时可选恢复 Stage 状态。Pop 遇到冲突保留 Stash；Drop 要求明确确认。操作绑定预览时的 Stash selector 与对象 ID，并校验完整 Stash reflog，禁止因序号移动误操作其他 Stash。
- Discard 全部文件后，History 中的恢复入口仍可用。二进制备份明确标为二进制，不显示有损文本，也不提供伪造的文本复制。所有手动 Git 操作独立于 AI Review，不会自动标记人工 Review 完成。

History 定位补充：工具栏固定显示当前本地 Branch 与 HEAD，可点击定位；图中 HEAD 标签和侧栏 HEAD 标记独立于正在选中的 Commit / 历史范围。HEAD 不在当前范围或已加载页面时，定位切到当前 Branch 历史。首次进入优先选中并显示已加载的 HEAD，后续刷新保留阅读位置；Detached HEAD 显示 Commit ID，尚无 Commit 的 Branch 禁用定位。
