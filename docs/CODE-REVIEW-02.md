# 安全丢弃与文件历史检查点

日期：2026-09-12。比较基线 `da7b7f6`，范围为本次未提交的 GIT-02、HIS-02、恢复存储与工作区身份校验。Standards 与 Spec 由两名独立评审只读检查，另使用隔离源码和真实 Git 仓库复现。原生 GUI 本轮未复验。

## Standards

- 中断后的 `applying` / `undoing` 状态原先无法继续恢复。已按保存版本与磁盘状态核对；缺失路径不会由普通撤销推断恢复，必须另行确认重建。7 个中断边界及重启测试通过。
- 256 MiB 容量检查与预留原先分离。两工作区并发能突破上限。现于 SQLite IMMEDIATE 事务中重检并预留，包含捕获副本实际增长；故障注入由红转绿。
- 捕获副本超过大小限制时曾令整个恢复查询失败。现独立报告副本预览警告，同时保留不可变 before/after 与目录访问。
- 取消先删目录、后删数据库，在数据库失败后无法重试。现支持“prepared 记录仍在但目录已缺失”的幂等取消，恢复内容查询也不依赖目录必须存在。
- Blame 曾把 clean filter 输出标为当前工作树。现逐行核对实际捕获内容，无法对应时明确降级，历史提交版本仍可查看。

- 旧格式恢复点增加逐记录格式版本；迁移前核对当前物理身份与旧基准，prepared 同时核对旧内容。共享 Git 目录被替换时保留旧审计归属并撤销旧信任，为新仓库重新登记工作区。旧格式成功/基准变化拒绝、linked worktree 重新打开回归通过。

## Spec

- 文件写后核对期间的外部删除曾被普通撤销重建。现普通撤销返回 `RECOVERY_MISSING_PATH` 并保持路径为空；`restore_missing_recovery` 是独立明确确认的创建动作，仍使用 no-replace 边界。
- 原 inode 被捕获后，外部旧 FD 的继续写入曾漏报。现安装后再次核对捕获内容，返回 `CAPTURE_CHANGED`，并保留后续编辑副本。
- 过期恢复内容原先可经详情入口继续读取。现启动、列表、新预览与详情入口均执行到期清理，写操作仍独立拒绝过期点。
- Git 八进制路径解码曾因 u8 中间值溢出而 panic。现先将每位转换成数值再相加，中文、换行及前导横线真实路径测试通过。

Spec 独立复核未发现新的阻断项；其隔离快照运行 45 个集成测试（含 2 个补充审查测试）和 3 个文件系统测试通过。主工作区随后补入取消重试、过滤器正文核对与 `.git` 替换回归，累计 49 个 Git 集成和 3 个文件系统测试通过。Standards 后续发现并复核了旧恢复指纹迁移与 linked worktree 共享目录替换的兼容修复，最终限定范围内未发现仍需处理的实质问题；该次仅复核源码与定向场景，没有重复全套测试。

## 限制

安全恢复当前以 macOS 同卷、普通 UTF-8 文本为验证范围。跨卷、硬链接、特殊文件、不能证明可逆的 Hunk 转换会拒绝操作。外部持有原 FD 时的未来写入无法被 Proof 停止；捕获 inode 会继续保留供检查。恢复点到期在应用启动或访问恢复功能时清理，不宣称应用退出后仍有后台清理服务。

文件历史与 Blame 保留为只读页面，未接入 Agent 作者推断。工作区身份校验增加了真实 Git 查询，性能预算与缓存优化仍待独立测量。完整 P0 状态见 IMPLEMENTATION.md 与 ACCEPTANCE.md。
