# 本地诊断

设置 → 诊断 → 选择附加内容 → 生成预览 → 保存到本地。导出为单个 JSON 文件，不需要网络，也不会上传。预览和保存是两个明确动作；取消系统保存对话框会返回预览。

## 默认内容与可选内容

默认包含 Proof/适配器版本、平台、已知 Git/Agent 版本、产品能力、安装状态、观察缺口的固定错误码和计数、Collector 的最近心跳及队列状态，以及本次进程的操作计时摘要。Git 版本来自最近成功的 Worktree 读取，Agent 版本来自显式检测或安装记录；生成诊断不会启动 Git、Agent 或模型，也不会读取 Agent 历史。未测量/不可用字段保留为 `null` 或 `unavailable`，过期心跳标为 `stale`。

默认不包含源码、prompt、Agent 回复、命令、原始输出、绝对路径、远程 URL、凭据、会话 ID、仓库名称或原始错误详情。数据从固定字段构造，不能把日志先复制出来再依靠正则脱敏。未知错误码归入 `UNCLASSIFIED_ERROR`，仍保留计数。

附加内容分别确认：

- **本地路径**：Worktree、Git、Hook 配置文件与 Proof 数据目录的位置；不读取配置正文。最多列出 128 个 Worktree 和 128 个 Hook 配置位置，截断有标记。
- **事件缺口时间线**：最近 100 条保留期内的缺口时间、固定错误码和数量；不包含会话内容或标识符。

性能摘要记录原生命令处理耗时，包括调度等待，不代表单独 Git 执行、浏览器绘制或端到端使用体验。采用有限命令/错误词表和固定直方图区间；不保存参数、错误正文或无限事件明细。指标在进程退出或本地记录清理后清空，旧代次的晚到样本不能重新填入。完成响应后不会为了记指标重新等待 Git 核心锁。Collector 的 queued/processing 使用独立计数，报告说明来自最近一次心跳。

## 预览、保存与删除

预览仅保存在内存：有效期 5 分钟、每类最多 4 份、普通诊断上限 256 KiB。返回内容是不可编辑的导出预览；后端保留原文与摘要，保存请求只能带预览 ID 和摘要。更改类别或取消预览会撤销旧预览。界面定期验证普通预览；保存期间停止该验证，避免将已消费的预览误报为失效。

目标位置必须来自原生 Save 对话框。保存实际使用预览原文，新文件权限为 0600；拒绝覆盖已有文件、最终路径 symlink，以及位于 Proof 数据目录（含别名）内的目的地。Unix 保存绑定目录描述符，完成后核对目录/文件身份。写失败不会按路径删除可能已被替换的文件，而会说明可能留下不完整的用户导出文件。

普通诊断的正文与创建时的数据代次一起冻结，不能在删除后重新绑定新代次。保存前取得 SQLite writer lease，再次核对代次与有效期，文件发布期间保持删除顺序保护；磁盘 I/O 在 Git 核心锁之外执行。SQLite 的 READWRITE 打开标志可能回退只读，因此会检查实际连接状态，不能把只读事务当成 writer lease。

用户导出的副本需要用户单独删除，清理 Proof 本地记录不会删除这些副本。

## 本地存储故障

数据库打不开时，Proof 保留错误并显示窗口，“打开诊断”仍可用。选择 **仅导出应用信息**，通过独立的原生接口生成公开的应用版本、平台、适配器版本、固定启动/诊断错误码；不访问数据库，不包含旧记录、路径或历史指标。报告标记 `application_only`、`localRecordsRead: false`，并列明不可用部分。它不能用于判断 Git 或 Agent 当前是否健康。

应用信息的正文只能由固定构造器生成。普通诊断 ID、调用者修改后的返回正文或任意 IPC 参数，都不能通过此入口进入不依赖数据库的导出任务。这个入口只保证故障诊断可达，不会自动修改文件权限或修复、替换数据库。

## 验证

- 10 条实际核心/临时 Git 诊断测试，加 2 条内部过期/删除交错测试：默认字段排除、独立类别、原文一致性、0600、取消、失效、重复保存、已有文件/symlink、DataScope::All 和观察清理、真实安装状态、只读回退、数据目录故障、别名及不可伪造应用报告。
- 3 条诊断 UI 测试：逐类确认与系统取消、慢保存、其他窗口清理后的失效，以及 Core 无法启动时的独立导出入口。
- 两组真实 macOS 原生窗口：正常预览/取消/过期拒绝/保存；Core 初始化失败后的应用信息预览与实际保存。隔离数据与 Agent 配置目录，未修改真实 Agent 配置。
- 本机证据：`.artifacts/diagnostic-native-01/acceptance.json` 和 `.artifacts/diagnostic-native-02/acceptance.json`；各自保存精确二进制哈希与导出文件哈希。它们是调试构建流程证据，不当作后续 Release 二进制的同哈希验收。

## 设计依据

参考 [VS Code Issue Reporter 的 Preview / Create 分离](https://code.visualstudio.com/updates/v1_104#_issue-reporter-improvements)，Proof 采用本地预览与本地保存，不接入问题发布或诊断上传。范围依据 PRD SET-03、SET-02、21.3、23.4 与存储故障诊断要求。
