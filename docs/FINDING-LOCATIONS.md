# Finding 定位

点击审查问题后，在现有代码区域打开只读位置视图，默认读取当前 Worktree；可切换到审查原位置，刷新位置或返回原 Diff。位置不要求仍属于当前变更块。人工 Reviewed、问题处置、Index 和源码保持原流程。

审查完成时，保存对应版本的有限代码基线：staged 的 old/new 为 HEAD/Index，unstaged 为 Index/Worktree，历史比较为固定 base/target。基线按来源和路径去重，不包含在普通报告与任务列表的返回值中。单文件上限 1 MiB、10 万行，基线总预算 4 MiB；无法保存的范围保留限制说明。

定位通过服务端保存的报告或任务及 Finding 序号读取；界面不能提交任意原始代码作为可信基线。查询校验当前数据世代、报告所属仓库、仓库身份与信任。

## 当前位置

- `exact` / `shifted`：原范围仍可明确对应，定位并高亮当前代码。
- `modified`：代码范围已改写，打开当前对应范围并显示待复核。
- `deleted`：原代码已删除，显示邻近上下文；文件不存在时可以查看原版本。
- `ambiguous`：重复代码或对应不唯一，界面不自动选择；用户选候选后仍需确认。
- `unavailable`：基线、编码或读取范围不可用，说明限制；可读取的当前文件仍供查阅。

原行被删除、别处出现同文代码时不能仅凭文本唯一就声称精确定位。行映射应结合真实版本差异与上下文。可靠 Git 改名信息可跟随当前路径；不能证明路径关系时保留限制。

当前位置与问题是否已修复分别呈现：找到、改写或删除代码都不会自动把问题标记为已解决。

## 旧记录

旧本地报告没有保存源码锚点，不能重建已变化的 Worktree/Index，只展示当前可读取代码与限制。固定历史提交仍可按原 OID 恢复原位置。

## Sidebar 与 Codex

Sidebar 原生结果与既有本地报告使用同一位置视图。定位完成/过期审查结果不依赖旧审查读取授权继续有效。原生审查优先使用 Codex 自身的只读文件、搜索、Shell/Git 与子 Agent；Proof MCP 负责核对任务、可选快照读取、公开进度与结果回传。完整原生工具活动仍在 Codex 会话中，Proof 显示可观察的工具活动与主动回报。
