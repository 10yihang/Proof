# 完整文件阅读与搜索

本轮补齐 DIFF-02 的文件内搜索与上下文阅读，并保持 DIFF-01/03/05/06 的比较基准、原始 Patch、Hunk 身份和阅读位置约束。Changes 与独立历史 Diff 共用阅读器；历史选择入口和 Commit 页职责不变。

## 交互

Diff 工具栏直接提供 `−` / 行数 / `+`，每次增减一行，旁边独立 `Full file` 按钮显示完整文本。再次点击回到此前行数；在全文模式点击增减按钮则从此前行数增减一行并退出全文。默认 3 行，最少 0 行。搜索跟随实际已加载范围，全文读取后可以查找未改动区域。`Cmd/Ctrl+F` 打开当前可见阅读器的搜索；对话框和其他输入框保留自己的键盘行为。Enter / Shift+Enter 跳转匹配行。

搜索期间临时显示被空白筛选折叠的代码，关闭后恢复原筛选。它不修改用户偏好、Git 内容或 Review 状态；Review 的空白筛选保护仍保留。读取上限或故障保留原 Diff 和实际搜索范围，不把加载失败显示成已完成全文搜索。

参考依据为 [Fork 的 Diff 内搜索说明](https://new.fork.dev/blog/posts/forkwin-1.38/)及 [GitKraken 的 Diff 阅读指南](https://support.gitkraken.com/working-with-commits/diff/)。后者区分关注变化块的 Hunk 视图与需要完整文件上下文的阅读。Proof 的范围选择器是本项目的具体实现，并非声称复制了对方的完整交互。

## 内容边界

Worktree 使用已有不可变 Diff 快照，先后校验源内容，并核对原 Patch。历史比较使用冻结 OID，比较 ID 包含实际 Patch；缓存命中前也核对当前生成的比较是否与这个 ID 一致。历史结果不登记为可写快照。

更宽的 Git Hunk 可以合并原分块，但返回结果只把未变化行补进原 Hunk 之间的间隔。原 Hunk ID、Review 标记和可执行 Patch 保持。重命名沿用同一 literal pathspec 处理。

完整上下文在进程输出阶段限制为 4 MiB，解析前限制为 100,000 行（包含 Patch 头）。超限终止本次读取并返回 `CONTEXT_TOO_LARGE`。上下文缓存最多 8 项、合计保留容量 8 MiB；不缓存超出容量的单项。文本摘要、纯元数据和特殊文件继续使用相应入口，不伪造完整文本。

两种上下文命令进入已有的窗口专属读取票据，支持取消和过期回复丢弃。取消及失败同时回退当前范围与书签，切回文件不会重启已放弃的读取。

## 阅读状态

隐藏的完整上下文会释放。每文件书签保留范围和源行位置，即使大 Diff 本体卸载，返回仍可恢复选择的范围。所需范围尚未重新加载时冻结书签，用户主动滚动或导航可以接管。新快照在首次位置恢复前处理范围，避免先按三行上下文覆盖旧书签。

范围进入并排横向测量键；从包含长未改行的全文缩回 Diff 时重算宽度并钳制偏移。自动重载保留当前搜索匹配，不无条件跳回首项。
