# 观察传输与数据保留检查点

日期：2026-09-12；比较基线 `252e925`。范围为新增观察核心/独立桥接、授权和工作区边界、数据保留/清理、Unix 进程退出，以及设置页的数据入口。Standards 与 Spec 独立只读评审，使用临时源码和真实 Git/SQLite/socket 夹具复现。真实 Agent 兼容与原生数据管理交互未纳入已通过范围。

## Standards

1. 服务停止曾等待被 Git 或继承输出管道阻塞的 worker。改为非阻塞进程 I/O、整个管道生命周期的 deadline、独立采集进程停机取消与 2 秒收尾期限。独立回归验证继承管道、双输出背压、提前失败退出码、采集停止及普通提交，均通过。
2. WAL checkpoint 后清空单一 pending 标志可能覆盖另一连接刚发生的删除。改为清理代次与已完成代次；旧 checkpoint 只能确认它捕获的代次。使用 SQLite authorizer 构造确定性交错，验证新的删除仍显示 pending，释放 reader 后敏感测试串从 DB/WAL 中清除。
3. 用量扫描可能碰到正在原子改名的 health 文件或被删除的目录。非根路径的 ENOENT 现在跳过，根目录缺失和其他错误仍报告。并发改名下 10,000 次扫描通过。

该限定范围内 3 项实质发现已修复并复核，没有待处理的 Standards 阻断项。后两项夹具已保留为 core 单元测试。

## Spec

1. 排队事件曾在暂停/恢复后取得新的字段授权。现在接收时捕获授权代次和 GUI 租约，处理前及提交事务内重检；新授权不能补给旧事件。
2. 父仓库授权曾覆盖未授权的嵌套 Git 仓库。现在排除嵌套 `.git` 目录/文件边界，linked worktree 补充夹具也通过。
3. 自定义名称且位于工作树内的实际 Git 元数据目录曾被漏掉。现在同步排除规范化 git_dir/common_dir 子树。
4. 取消恢复预览删除了数据库行，却没有要求清理 WAL 中的旧源码副本。删除与清理代次现在同一事务提交；原始数据库/WAL 字节回归通过。
5. 清空事件后的 SQLite freelist 曾使物理数据库仍占用限额，无法恢复采集。现在按容量压力和可回收空间执行 VACUUM，空间回收失败单列 pending；真实事件行与稀疏压力夹具验证清理后可恢复采集。
6. 入库预留空间与设置页“已暂停”状态曾使用不同阈值。现在入库、状态与回收判断共用预留阈值，规范化事件单独封顶；仅剩少量空间时状态一致。

该限定范围内 6 项实质发现已修复并复核。最终独立复核为 17 条观察回归及 1 条补充回收测试通过；补充测试还验证旧 reader 阻止回收时保留 pending，释放后清理与采集状态恢复。没有待处理的 Spec 阻断项。
