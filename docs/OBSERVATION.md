# Proof 本地观察实现状态

需求基线为 PRD 的 OBS、CTX、EVD、SEC、SET 与第 21 章。本文描述 2026-09-12 的开发实现，**不是 Agent 正式支持矩阵**。

## 传输与授权

`proof-observer bridge --registration <文件>` 读取 stdin，转交同用户 Unix socket。注册文件要求当前用户所有、普通文件、0600 权限；凭据不放在命令行，SQLite 仅存凭据指纹。桥接保持 stdout/stderr 为空，带有从程序入口开始的 50 ms 自身期限与 watchdog；不执行 Git、SQLite、模型或 GUI 操作。启动前的系统错误或系统强制终止仍可能暴露给上游，不能宣称绝无影响。

协议为 4 字节大端 header 长度、最多 1 KiB JSON header、最多 2 MiB 原始负载。服务端验证版本、长度、注册身份和 Unix peer UID；socket 0600、父目录 0700。服务使用排他租约，另一进程不能移除活动 socket。退出时只清理仍属于自身的 socket 文件。

接收端最多 8 个连接、4 条排队记录，每个未完成连接最多保留 200 ms。重处理在独立线程进行。接收时捕获授权代次与 GUI 前台租约；处理前及入库事务中重新检查。暂停、字段变更、撤销信任、清理记录都会使旧授权代次失效。事件不能在暂停后恢复或 GUI 重新打开后取得新的权限。

后台观察是每个工作区的独立授权，默认关闭。独立服务 `serve --data-dir <目录>` 读取短期前台租约；租约消失且没有后台授权时停止。SIGTERM/SIGINT 仅停止本采集器。停机取消其自身启动的 Git 读取，2 秒未能收尾则退出并留下不完整性标记；不向 Agent 发信号。GUI 控制器、稳定 helper 安装路径及自动续租尚待接入。

## 记录含义

- 先解析真实 Git 工作区，再匹配本地工作区 ID；独立 clone、linked worktree、嵌套仓库不因分支名相同而共享授权。
- 文件路径限制在授权工作区内；排除嵌套 Git 边界、实际 git_dir/common_dir 与 `.git` 元数据。内容匹配使用绑定父目录的只读文件句柄，只保留匹配 hash，不复制整个仓库。
- 已授权 prompt、命令、最终回复、输出共享每事件 64 KiB 文本预算。未授权字段不持久化；不读取 transcript 文件。原始上游负载可能包含敏感内容并进入进程内存，不承诺其从未被接收。
- 使用原生事件 / 工具调用 ID 去重；缺少可靠 ID 时保留记录并标记可能重复。本地 ID 明确来自 Proof。
- 仅结构化退出码能支持命令成功/失败。Post-only 事件默认 `unconfirmed_post_only`；命令成功不会生成测试用例计数或当前代码已验证结论。
- `receiving_unverified` 仅表示收到格式可处理的事件，不表示该 Agent 版本已通过真实兼容验证。

Context 面板的会话浏览、人工关联修正、完整性及验证时效呈现尚待接入。底层匹配 hash 不等于当前 Hunk 的独占作者证明。

## 保留与清理

命令输出 7 天，任务/事件/会话/关联备注 30 天，Review 与操作记录 180 天。恢复点继续按 7 天 / 256 MiB 的独立规则处理。到期输出清空并标为 `expired`；事件到期删除，对应无剩余事件的会话清理。

应用打开、访问观察记录、数据管理操作时执行维护；独立采集器运行期间每分钟检查一次。应用及采集器都退出时不宣称仍有后台清理。

“暂停并清理观察记录”把暂停、授权代次更新、事件/会话/人工关联删除放在同一事务。源仓库移动或不可访问时仍能清理本地记录。它保留 Git 源码、Agent 原历史、Proof Review 与未到期恢复点；不是整个应用卸载。

数据库使用 secure_delete；删除与清理代次一起提交，再尝试截断 WAL。旧读者或并发清理阻止完成时保留 pending，不显示磁盘副本已经清除。取消与到期恢复预览同样纳入该流程。此机制不承诺擦除操作系统快照、备份或用户自行导出的文件。

全应用采用 2 GiB 软上限，并预留单条规范化事件及其数据库日志所需空间。入库、设置页状态和回收判断使用同一阈值。清理后必要时回收 SQLite 空闲页；回收失败与记录删除分别报告，可重试。统计目录有深度和条目数上限，达到上限时显示已有用量的下界并暂停内容采集，不伪造完整用量。
