## 操作范围

- 暂停观察保留已有记录；清理某 Worktree 的观察记录则先撤销其授权，再删除任务、事件、会话与关联备注，保留 Git/Review/恢复点。
- 从最近项目移除只隐藏入口；已登记身份、信任、Review、观察授权和项目文件保留。数据管理仍能列出隐藏项目，显式重新打开会恢复最近入口；路径已不存在时仍可移除和删除本地记录。
- 删除一个仓库的 Proof 记录覆盖它的全部已登记 linked Worktree；独立 clone 使用不同 repository UUID，不在同一范围内。删除 Review、观察、操作记录、恢复点、仓库布局与编辑器覆盖，移除工作区身份及信任。重新打开使用新 UUID 并重新确认信任。
- 删除全部记录同时清所有仓库、应用偏好、编辑器配置、注册身份、Commit 草稿、文件树显示偏好与恢复副本，并停止当前采集器。源仓库、Git 配置/Hook、Agent 自身历史和外部导出/系统备份不被删除；尚未实现的真实 Hook 安装/卸载流程不在本次执行范围内。

## 持久化和并发

schema 4→5 增加隐藏最近项目、前端清理标识和磁盘清理任务；schema 6 增加全局 Hook 配置回执及连通探测确认。原表不改变列布局。SQLite secure_delete 与 WAL 清理继续使用已有流程。数据清理只处理 Proof 的恢复目录、临时 Index、Hook 安装备份/凭据和固定运行状态文件，不遍历源仓库。需要移除的 Agent 配置会在删除预览中列出，并在写入前核对范围。

删除先生成有 5 分钟有效期的原生预览，固定仓库及 Worktree UUID；确认时在 immediate transaction 中重新检查范围和数据版本。后台新增了仓库/Worktree 时拒绝旧确认。范围内的记录按确认时状态全部删除。SQL 失败回滚；SQL 提交后的磁盘失败返回“记录已删除、磁盘清理待重试”，不伪装成没有发生删除。

恢复文件清理在逐级 no-follow 目录句柄上进行，只 unlink 固定文件名；目录身份不符、符号链接目录、忙碌的恢复操作或未识别内容不会被遍历。SQL 写事务阻止新的恢复操作写入 applying/undoing 状态；现有恢复 lease 逐个检查，避免同时打开所有恢复目录。已提交的清理任务跨重启继续执行。普通 backup symlink 只删除链接本身，不跟随目标。

临时 Index 现在存放于 `transient/<workspace UUID>/<operation UUID>`，创建时在 SQL 写事务中验证身份，使用期间持有独占 lease。删除时按仓库登记持久化任务；正在运行的 Git 操作可完成，磁盘清理等待其 lease 释放，空的旧 workspace 目录也会移除。旧版 `.tmp*` 和 `sharedindex.*` 只作为共享、可丢弃缓存处理，发现任一已登记仓库的 Index 锁时先拒绝；未知内容不递归删除。已开始的 Commit 可以成功改变 Git，但删除后的 workspace 不能重新插入 Proof 操作记录，界面仍报告真实 Git 结果及记录未保存的提示。

`data_epoch` 在删除后推进。每个挂载组件的请求接口捕获 renderer 代次，每个请求携带当时的数据版本，原生 dispatch 在操作锁内验证；删除前尚未发出的排队回调也不能取得新版本继续写入。旧请求不重放。返回晚于删除的读取结果也被丢弃。renderer 重新挂载以清掉隐藏的 History/Context、Diff 和设置草稿；未被删除的当前仓库可重新读取。全局删除版本另约束采集器的运行文件与 gap 写入，同一 SQL 事务将小型元数据写入与删除排序，旧采集器退出时不会重新写回。新采集代次复用固定文件名之前，先在同一写事务内完成旧 runtime 清理任务；清理器也会重新确认任务仍存在，不能用旧任务列表删除新文件。

Commit 草稿目前在 renderer localStorage。仓库删除留下不含路径/正文的 UUID 清理标识，全局删除留下清理代次；renderer 启动必须先处理它们再读取草稿。草稿和文件视图按全局清理代次使用不同键，写入槽同时包含完整数据版本；清理版本使用不可变的代次键取最大值，并在枚举删除范围前发布，阻止旧窗口继续写入。写入落盘后再次校验，迟到的旧写入只撤销自己的旧版本槽，不能误删另一窗口的新数据。一个窗口的晚到响应只能清理更早代次以及明确被删除的 UUID，不能删除另一窗口的新草稿或倒退共享版本；无关应用键保留。缓存清理失败不会恢复旧草稿，并提示重试。这些内部计数与 UUID 不是被删内容的副本。
